# Слой 3: Кастомизация экрана реконструкции

## Назначение

Переработать первый экран виджета («Логическая реконструкция»), который по умолчанию выглядит так:

- **Левая колонка** — вся проза реконструкции кирпичом + таблица.
- **Правая колонка** — пустая (`<div class="insights"></div>`).

После Слоя 3:

- **Левая колонка** — 4–6 коротких абзацев + опциональный SVG + блок «Главная идея».
- **Правая колонка** — «Артефакты урока»: цветные карточки с файлами, промптами, лайфхаками, ресурсами, домашкой.

Слой 3 не трогает `md_parser.py` и `widget_generator.py` — это **post-processing патч** поверх готового виджета. Слой 1 и Слой 2 остаются неприкосновенными.

---

## Когда применять

Пользователь сказал одно из:

- «оживи первый экран»
- «кастомизируй реконструкцию»
- «сделай как в М2-У6/У7»
- «заполни правую колонку»

## Принципы

### Левая колонка

**Цель левой колонки — дать пользователю взгляд на урок сверху.** Прочитал 4–6 абзацев — увидел картину целиком: о чём этот урок, что автор хочет донести, какая в нём логика. Дальше уже идёт в детали (сегменты, виджеты-карточки) с готовой структурной рамкой в голове.

Это **не пересказ сегментов** и **не литературоведческий разбор** «риторической дуги». Это **карта урока для читателя**, написанная так, чтобы её было легко воспринимать.

#### Язык

Простой, разговорный, как объясняешь другу. Без оборотов вроде «риторическая дуга разворачивается на 180°», «фундамент держит первую половину», «глубинное "зачем"». Если читатель должен расшифровывать твои слова — ты пишешь для себя, а не для него.

**Тест:** прочитай абзац вслух. Если он звучит как человек объясняет суть урока — нормально. Если как литературовед или преподаватель риторики — переписывай.

#### Что должен увидеть читатель

Из 4–6 абзацев читатель должен понять:

1. **О чём вообще урок** — на какой вопрос отвечает.
2. **Что автор хочет донести** — главная мысль, ради которой урок снимался.
3. **Как устроена логика** — что идёт за чем и почему.
4. **Есть ли поворот** — если автор сначала что-то утверждает, а потом ограничивает («но», «однако»), читатель должен увидеть этот поворот сразу, а не наткнуться на него в середине.

Конкретика (метафоры, цифры, имена, термины) — из Карт и Текста сегментов. Голос спикера сохраняется. Жирное в каждом абзаце — по правилу из SKILL.md (раздел «Навигация в Тексте»): сжатая мысль абзаца.

#### Как строить абзацы

**Шаг 1. Прочитать Главную мысль шапки и найти в ней связки.** «Но», «потому что», «и», противопоставления — это подсказки про логику урока. Слово «но» в Главной мысли почти всегда означает, что в уроке есть поворот: автор сначала утверждает, потом ограничивает. Этот поворот должен быть виден в реконструкции отдельным абзацем.

**Шаг 2. Назвать темы абзацев.** 4–6 коротких рабочих заголовков типа «о чём урок», «что такое X», «зачем это нужно», «когда это НЕ надо делать», «где применяется». Эти темы — не сегменты выступления, а **слои понимания** для читателя.

**Шаг 3. Проверить, что абзацы не идут по сегментам.** Если над каждым абзацем можно подписать номер сегмента и всё совпадёт по порядку — это пересказ, не реконструкция. Переделать.

**Шаг 4. Написать абзацы простым языком.** Каждый абзац — 2–4 предложения. Один абзац = одна мысль = один слой картины. Без литературщины.

#### Антипаттерны

**Не делать:**

- **Пересказ сегментов по порядку.** Абзацы соответствуют сегментам 1-к-1. Признак: можно подписать над каждым абзацем номер сегмента, и всё совпадёт.
- **Литературоведческий разбор.** «Риторическая дуга», «слом в шапке», «фундамент держит первую половину» — это анализ для агента, не текст для читателя. Читателю надо ПОНЯТЬ урок, а не выучить, как устроено выступление.
- **Потеря поворота.** Если в Главной мысли есть «но» / «однако» — а в реконструкции нет абзаца, где автор разворачивается, — карта плоская. Пропущен главный посыл урока.
- **Абстракция без конкретики из сегментов** — текст, который можно было бы написать, не читая лекции.
- **Потеря Главной мысли шапки как ведущей нити** — каждый абзац должен в неё стрелять, а не уходить в сторону.
- **Дословное повторение Ключевых мыслей сегментов** — это сжатие, а не объяснение для читателя.

#### Опциональный SVG

Вставляется между прозой и блоком «Главная идея» (см. раздел про SVG ниже).

#### Блок «Главная идея»

Всегда в конце левой колонки. Синий blockquote-стиль:

```html
<div style="background:#ECF2FB;border-left:3px solid #2562B0;border-radius:0 8px 8px 0;
padding:10px 14px;margin:14px 0 6px;font-size:13px;line-height:1.55">
<strong>Главная идея:</strong> [текст]</div>
```

### Правая колонка

«Артефакты урока» — что есть в этой конкретной лекции. Состав не догма. Типовые секции:

| Секция | Когда ставить |
|---|---|
| Файлы в проекте | Урок создаёт/использует именованные файлы |
| Промпты | Есть промпты, которые пользователь будет копировать |
| Лайфхаки | Есть практические приёмы/горячие клавиши/команды |
| Ресурсы | Есть ссылки/сервисы для насмотренности |
| Что сделать после урока | Всегда, если есть домашнее задание |

Структура каждой секции: **заголовок + карточки**. Инструменты — `section()`, `file_card()`, `prompt_card()`, `link_card()` из шаблона.

### Кликабельность (привязка к сегментам)

Используй уже существующую в движке функцию `goTo('NN')`, где `NN` — двузначный id сегмента (`'01'`, `'02'`, ...).

**Правило:**
- Если **все элементы секции относятся к одному сегменту** → одна стрелка `↗` на **заголовке** секции (`goto_id` в `section()`), у карточек — без стрелки.
- Если **элементы внутри секции относятся к разным сегментам** → индивидуальные стрелки `↗` у каждого элемента (`goto_id` в `file_card()` или `prompt_card()`), заголовок секции — без стрелки.

**Важно:** стрелки внутри `<details>` (в `prompt_card`) используют `event.stopPropagation()` в `onclick`, иначе клик на стрелку разворачивает промпт. Шаблон уже содержит это — не удалять.

## SVG: когда нужен и когда нет

### Нужен

Если в лекции есть **операциональная схема**: цепочка артефактов, параллельные процессы, цикл, иерархия. Схема даёт визуальный якорь, которого проза не даёт.

### Не нужен

Если лекция — про тезис, метафору, дискуссию, разбор кейса без чёткой схемы. Натянутый SVG хуже, чем его отсутствие.

**Если сомневаешься — не делай SVG. Обойдись прозой.**

### Типовые формы SVG (с референсами)

| Форма | Описание | Референс |
|---|---|---|
| Параллельные ветви → один артефакт | N агентов запускаются одновременно, результат идёт в один файл | `patch_recon_m2u6.py` |
| Горизонтальная цепочка + правки | Файл → промпт → файл → промпт, с кружками «✎ правка» между шагами | `patch_recon_m2u7.py` |
| Цикл / обратная связь | Результат возвращается на вход | — |
| Иерархия / дерево | Концепты / уровни вложенности | — |
| Сравнение «было → стало» | До и после применения метода | — |

**Технические принципы SVG:**
- `viewBox="0 0 540 280"`, `display:block;width:100%;height:auto`
- Фон `#F8F6F1`, рамка `rgba(60,52,36,.15)`, радиус `10px`
- Шрифт `'Manrope',system-ui,sans-serif`
- Монопространные имена файлов — `font-family="JetBrains Mono, monospace"`
- Цвета: синий `#2562B0` (файлы/артефакты), зелёный `#2E6E2E` (результат/вывод), оранжевый `#96580F` (действия/правки)
- Маркеры стрелок — именованные `<marker id="arr-[урок]">`, чтобы не конфликтовать между инстансами

## Шаги

1. **Прочитать `_мастер.md` лекции.** Собрать иерархию источников для левой колонки:
   - **Главная мысль шапки** (`**Главная мысль:**`) — фундамент дуги, одна формулировка риторической позиции автора.
   - **Ключевые мысли сегментов** (поле `**Ключевая мысль:**`) — короткая выжимка содержимого, прямо подсказывает темы для абзацев.
   - **Карта сегментов** — структурированный список тезисов, термины и формулировки в готовом виде.
   - **Текст сегментов** — конкретика, метафоры, цифры, имена инструментов (для разворачивания абзацев без потери голоса).
   - **Таблица в Логической реконструкции** — каркас риторических ролей и ключевых ходов, подсказывает последовательность абзацев левой колонки.

   Дополнительно для правой колонки выписать: список сегментов с id, все файлы/артефакты, все промпты, лайфхаки, ресурсы, домашку.

2. **Решить про SVG.** Есть ли операциональная схема? Если да — какая форма (из таблицы выше)? Если сомнения — пропустить.

3. **Составить состав секций** правой колонки. Какие из типовых секций нужны для этой лекции? В каком порядке?

4. **Определить привязки к сегментам.** Для каждой секции и каждого элемента — к какому `id` сегмента он относится? Применить правило «групповая vs. индивидуальная стрелка».

5. **Создать patch-скрипт** `patch_recon_<урок>.py`:
   - Скопировать `recon_patch_template.py` → новый файл в корне проекта.
   - Заполнить все TODO-секции: `WIDGET`, `BODY_00`, контент карточек.
   - Если нужен SVG — нарисовать `SVG_SCHEME`, вставить в `BODY_00`.

6. **Запустить, открыть виджет, оценить.** При необходимости — итерировать. Когда доволен — финальный виджет лежит в `transcripts/`.
