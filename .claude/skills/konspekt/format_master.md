# Формат мастер-MD

**Единственный источник контракта.** Всё, что описано здесь, разбирает `md_parser.py` и рендерит `widget_generator.py`. Отступление от формата ломает виджет молча — генератор напечатает `✅ JS syntax OK`, потому что синтаксис JS валиден, а структура нет.

Кто читает файл:
- **мастер-режим** (`master.md`, ШАГ 2) — чтобы писать по контракту;
- **Слой 2** (`layer2_widget.md`) — чтобы понимать, что именно парсер вытащит из мастер-MD.

## Шапка файла

```markdown
# [Заголовок, выбранный пользователем в 1.2]

**Спикер:** [имя]
**Длительность:** [HH:MM:SS]
**Профиль:** [лекция / custdev / встреча / конференция]
**Главная мысль:** [одна формулировка главной мысли из 1.2]
**Сегментов:** [N]

---
```

**Шаблон раздела «Замысел и маршрут» (вставляется сразу после шапки, если блок 1.3 был открыт):**

```markdown
## Замысел и маршрут

[4–6 коротких абзацев прозы «взгляд сверху» — дописываются в конце ШАГ 2.
До этого момента раздел содержит только заголовок и опорную структуру.]

**Этапы:**

1. **Этап 1 — <глагол>: <суть>** — почему отсюда начинаем / что даёт.
2. **Этап 2 — <глагол>: <суть>** — почему за предыдущим следует это.
   ...
```

Имя маркера опорной структуры зависит от формы:
- `**Этапы:**` — методология (нумерованная лестница);
- `**Тезисы:**` — лекция-идея (ключевые мысли);
- `**Опорные точки:**` — разбор с аркой.

Парсер `md_parser.py` ищет любой подзаголовок вида `**...:**` на отдельной строке — имя маркера на разбор не влияет.

## Разделители секций

**Разделитель `---` между секциями (обязательно).** Каждая верхнеуровневая секция мастер-MD разделяется строкой `---` на отдельной строке: после шапки `# Название`, между каждым `## Сегмент N`, перед `## Замысел и маршрут` и перед `## Логическая реконструкция`. То есть `---` стоит **перед каждым** `##`-заголовком верхнего уровня (кроме первого, идущего сразу за шапкой). Парсер режет файл по `\n---\n` (`md_parser.py`, `_split_sections`); если пропустить хоть один разделитель, соседние секции склеятся в один блок, виджет соберётся битым (первый экран пуст, реконструкция не разберётся), а генератор при этом напечатает `✅ JS syntax OK` — синтаксис валиден, структура нет.

## Шаблон сегмента

````markdown
## Сегмент N | HH:MM:SS–HH:MM:SS | [Тема]

**Тип:** [риторическая роль: инструкция / демонстрация / тезис / разбор кейса / Q&A / отступление / комбинации через «+»]
**Спикер:** [имя]

**Ключевая мысль:** [1–2 предложения — что главное в этом сегменте]

### Карта

- **[Тезис/термин]:** [пояснение]
- **[Другой тезис]:** [пояснение]
- ...

### Текст

[Очищенный транскрипт сегмента в голосе спикера. 70–90% объёма транскрипта по знакам.

Если несколько подтем — членение через `#### подзаголовок`.

При **явных** формулировках спикера могут стоять блоки `> **Метка:** ...` — см. «Метки блоков» ниже.

Не ставить блок формально — только если спикер реально это сформулировал.]

*[Переход к следующему сегменту, 1–2 предложения в голосе спикера. Между последним сегментом и концом — переход не нужен.]*
````

## Метки блоков

Единственный канонический список. Метка задаёт **уровень** блока, уровень задаёт цвет в виджете (`layer2_widget.md`) и разбирается `md_parser.py` (`LABEL_TABLE`). Добавляя метку — добавлять во все три места сразу.

| Метка | Уровень |
|---|---|
| **Ключевая идея**, **Главная идея**, **Принцип**, **Лайфхак** | (И) идея |
| **Методология**, **Критерии**, **Правило**, **Шаблон**, **Шаг N. Финальная формулировка** | (М) метод |
| **Пример**, **Пример декомпозиции**, **Демонстрация**, **Важно** | (Д) конкретика |
| **Промпт «...»**, **Скрипт «...»** | особый блок, см. «Вставка промптов» |

Метка может уточняться по смыслу («Критерии хорошей идеи», «Шаг 3. Финальная формулировка») — парсер ловит её по префиксу.

**Метки вне списка не изобретать.** Если метки нет в таблице, парсер определяет уровень эвристикой, а при промахе тихо ставит оранжевый — блок отрендерится не тем цветом, и никакой ошибки не будет. Нужна новая метка — сначала внести её сюда и в `md_parser.LABEL_TABLE`.

## Вставка промптов

Если в сегменте спикер показывает, зачитывает промпт или предлагает заскринить — промпт вставляется в Текст **дословно**, отдельным блоком. Это применимо к промптам из любого источника: скрины, презентация, надиктованный голосом, найденный в транскрипте.

**Источник приоритета (от точного к наименее точному):**

1. Скрин промпта (распознан в ШАГ 0).
2. Презентация (если промпт есть в слайдах).
3. Транскрипт (только если двух предыдущих нет).

Если есть скрин или презентация — текст берётся из них. Транскрипт в этом случае служит только для определения **места вставки** и **названия промпта** (как его называет спикер).

**Дословность.** Сохранять **всё**: нумерацию, маркеры списков, отступы, переносы строк, регистр, пунктуацию, кавычки, спецсимволы, переменные в `[квадратных скобках]` или `{фигурных}`. Не «причёсывать», не сокращать, не объединять строки. Если в источнике пустая строка между блоками — она остаётся.

**Формат блока:**

````markdown
> **Промпт «[название как у спикера]»:**

```
[текст промпта дословно из источника]
```
````

Метка может начинаться со слова **`Промпт`** или **`Скрипт`** (`> **Скрипт «...»:**`) — парсер принимает оба. «Скрипт» уместен, когда дословный блок — это не промпт для нейросети, а речевая заготовка (скрипт звонка, пул вопросов, реплики). Метка рендерится в виджете как есть, поэтому выбирай слово по смыслу содержимого.

Метка-blockquote — для единообразия с остальными блоками сегмента (`> Ключевая идея`, `> Методология` и т.п.). Fenced code block — потому что внутри `>` markdown мнёт переносы и непредсказуемо рендерит вложенные списки, а в code block структура сохраняется точно.

Если промптов в сегменте несколько — несколько таких блоков подряд, каждый со своим названием.

## Логическая реконструкция (технический минимум)

Раздел остаётся в файле **только как технический служебный блок** для Слоя 2 (виджет берёт из него содержимое первого экрана). Аналитика и проза в нём не пишутся.

```markdown
## Логическая реконструкция

> **Главная идея:** [одна формулировка — дословная копия `**Главная мысль:**` из шапки]

| Сегмент | Риторическая роль | Ключевой ход автора |
| --- | --- | --- |
| 1 | [роль] | [ход]                                                                  |
| ... | ... | ...                                                                          |
```

- **Цитата `> Главная идея:`** — дословная копия формулировки из `**Главная мысль:**` в шапке. Никакого переформулирования, никакого «более развёрнутого варианта».
- **Таблица** — только если сегментов > 1. Колонки — те же, что в навигационной карте из ШАГ 1.4.
- **Прозы в реконструкции нет.** Развёрнутая аналитика «как устроена аргументация автора» — это **внутренняя работа агента** (см. раздел «Три уровня (И)/(М)/(Д)»), а не текст в файле. Для человека-читателя весь смысл выступления уже передан Главной мыслью шапки и шестью сегментами.
- Если виджет в дальнейшем кастомизируется через Слой 3 — первый экран собирается заново по сегментам, эта реконструкция там не используется.
