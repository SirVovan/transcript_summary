# Скилл: /konspekt

Один проход Claude: транскрипт → мастер-MD.

## Файлы скилла

- `SKILL.md` — этот файл (методология + формат + самопроверка).
- `split_transcript.py` — нарезка длинного транскрипта на части по смысловым швам (ШАГ 0.3).
- `layer2_widget.md` — виджет (Слой 2), читается отдельно по запросу.
- `widget_generator.py` — сборка виджета из JSON (Слой 2).
- `validate_widget.py` — PostToolUse-хук валидации JS виджета.
- `profile_*.md` — профили контента по типу выступления; нужный читается в ШАГ 0.
- `_archive_2026-05-18/` — предыдущая архитектура (двухфазная с субагентами и бригадиром, заморожена 2026-05-18 как переусложнённая).

## Команды пользователя

- `/konspekt` + транскрипт → мастер-MD.
- `/konspekt — сделай виджет из <файл>` → виджет: Слой 2 + Слой 3 одним процессом (см. `layer2_widget.md`, затем `layer3_recon.md`).
- `/konspekt preview <путь или YouTube-URL>` → предварительный обзор видео (см. `preview.md`).
- `/konspekt split <файл> [--target-min N]` → **ручная** нарезка транскрипта на части (см. «Ручная нарезка» ниже). Без обработки в мастер-MD — только режет файл.

## ШАГ 0. Подготовка

Выполнить автоматически, без вопросов:

1. **Серийный контекст:** проверить **рабочую папку серии** (там же, где исходник — например, `konspekts/<серия>/`) на `*_мастер.md` той же серии. Если есть — прочитать **шапку + Карты + значения `**Ключевая мысль:**`** последних 2–3 уроков серии (Тексты сегментов **не читать**). Этого достаточно для эталона масштаба сегментации, стиля и калибровки голоса. Полный Текст конкретного сегмента читать только если возник точечный вопрос — например, как спикер раскрывал термин X в прошлом уроке.
2. **ToV-файл:** проверить `tov_<серия>.md` в той же рабочей папке серии. Если есть — прочитать, использовать в блоке голоса.
3. **Размер транскрипта (авторезка).** Прогнать `python "$HOME/.claude/skills/konspekt/split_transcript.py" info "<файл>"`.
   - Если вывод «Резать не нужно» (≤ 100 мин) — продолжать обычным пайплайном.
   - Если «резать на N частей» (> 100 мин) — выполнить нарезку **до** ШАГ 1:
     1. `python "$HOME/.claude/skills/konspekt/split_transcript.py" windows "<файл>"` — получить N−1 окон вокруг целевых точек.
     2. Для каждого окна выбрать тайминг шва по **правилу из вывода**: сначала вперёд (ближайшие 5–10 мин — не закрывает ли автор тему); если тема ещё активна — строго назад до ближайшего предыдущего шва; не резать посреди активной темы.
     3. `python "$HOME/.claude/skills/konspekt/split_transcript.py" split "<файл>" --at <шов1>,<шов2>,...` — создаст `<имя>_ч1.txt … _чN.txt`.
     4. Сообщить пользователю: разрезано на N частей. Дальше обрабатывать части **последовательно как серию**: `_ч1` пишет `tov_<серия>.md`, каждая следующая часть читает серийный контекст предыдущих (п.1 этого ШАГа) — отдельный полный проход и своё сохранение `_чN_мастер.md` на часть.

Затем спросить пользователя одним сообщением:

- Имя спикера (если не в транскрипте).
- Профиль: лекция / custdev / встреча / конференция (или «определи сам»).
- Сопроводительные материалы: есть ли презентация (.pdf / .md-вытяжка / .pptx) и/или скрины промптов (.png / .jpg)? Если есть — пути.

### Сопроводительные материалы

Если пользователь указал материалы — прочитать до ШАГ 1.

**Презентация.** Приоритет: `.md`-вытяжка → `.pdf` → `.pptx`. Если только `.pptx` — попросить экспортировать в `.pdf` или сделать текстовую выгрузку (Claude Code не читает `.pptx` напрямую). Из презентации брать: структуру выступления (ориентир для сегментации в ШАГ 1), заголовки разделов, чек-листы, точные формулировки промптов.

**Скрины промптов.** Прочитать каждое изображение через Read. Для каждого распознать текст **полностью и дословно**: сохранить нумерацию, маркированные списки, отступы, переносы строк, регистр, пунктуацию, спецсимволы. Зафиксировать в рабочей памяти с короткой меткой (например, «промпт-1: создание агента»). Куда вставлять — определяется в ШАГ 2 (там, где спикер показывает/зачитывает этот промпт или предлагает заскринить).

Если материалов нет — продолжать только по транскрипту, ничего не сообщать.

### Профиль контента

После выбора профиля прочитать `profile_<профиль>.md` (lecture / custdev / meeting /
conference; при «определи сам» — выбрать по содержанию и прочитать его). Профиль задаёт
принцип сегментации и допустимые значения «Тип» для этого типа выступления — учитывать
в ШАГ 1.3/1.4 и в шаблоне сегмента. `profile_base.md` — общая основа, читается всегда.

### Если ToV-файла серии нет

Прочитать первые ~3K токенов транскрипта. Извлечь и записать `tov_<серия>.md` в рабочую папку серии (рядом с исходником):

- Характерные обороты речи
- Темп и формальность
- Фирменные фразы и обращения к аудитории

Имя серии — из имени транскрипта (например, `ПОЛНЫЙ курс Claude Code 2026 ч2.txt` → `full-claude-code-2026`). Для следующих частей серии этот файл переиспользуется.

## ШАГ 1. Главная мысль и сегментация

### 1.1. Чтение

Прочитать транскрипт целиком.

### 1.2. Главная мысль и заголовок

До сегментации сформулировать:

1. **Главную мысль всего видео** в 1–2 предложениях. Это **риторическая позиция автора**, не тема: не «про GitHub», а «как не потерять наработки через сохранения в облаке». Ради чего автор делал это выступление, что должно остаться у слушателя как главное.
2. **2–3 варианта заголовка**, отражающих мысль с разных углов (акцент на пользу для слушателя / на место в серии / на главную операционную идею). Сколько вариантов — решить по содержанию: иногда 2 явно разных хватает, иногда нужно 3.

Показать пользователю → ждать выбор.

Выбранный заголовок становится:
- `# [Заголовок]` в шапке файла;
- значением строки `**Главная мысль:**` в шапке;
- ориентиром для замысла и маршрута (1.3) и сегментации (1.4);
- дословной копией в блоке `> **Главная идея:**` Логической реконструкции (без переформулирования).

### 1.3. Замысел и маршрут (условно)

До сегментации проверить, есть ли у материала **единая нить** — методология / развивающаяся мысль / разбор с аркой.

**Тест на нить:**
> Можешь сформулировать в 4–8 пунктах, что автор делает по порядку с начала до конца? Если да — нить есть, заводи блок. Если получаются разрозненные темы без преемственности — нити нет.

**Если нити нет** — этот под-этап пропускается, идти сразу к 1.4.

**Если нить есть** — сформулировать **опорную структуру** автора: 4–8 пунктов. Форма зависит от типа материала:

- методология → нумерованная лестница этапов: «Этап N — <глагол>: <суть> — почему отсюда / что даёт»;
- лекция-идея → список ключевых тезисов / поворотов мысли;
- разбор с аркой → опорные точки сюжета или акценты.

**Прозу «взгляд сверху» здесь НЕ пишем** — только опорную структуру. Проза дописывается в конце ШАГ 2, когда уже видны финальные сегменты.

Результат под-этапа — заготовка раздела `## Замысел и маршрут` в мастер-MD: только заголовок, маркер опорной структуры (`**Этапы:**`, `**Тезисы:**`, `**Опорные точки:**` — по форме) и список. Прозы пока нет.

**Примеры теста на нить:**
- **Есть нить** (методология): лекция «как создать персонального ассистента» — этапы 1) собрать промпт, 2) добавить контекст, 3) проверить ответы, 4) дописать ошибки. Последовательность видна.
- **Нет нити** (разговорный подкаст): обсуждают три не связанные новости + Q&A. Каждая тема самостоятельна.

### 1.4. Сегментация

Построить навигационную карту:

```
Сегмент 1 | HH:MM:SS–HH:MM:SS | [Тема] | [риторическая роль]
Сегмент 2 | ...
```

**Сегментация — от опорной структуры, если она есть (1.3).** Каждый сегмент = один пункт опорной структуры или его явная часть. Заголовки сегментов наследуют формулировки пунктов (для лестницы этапов — дословно; для тезисов / опорных точек — производные).

**Если опорной структуры нет** — сегментация от главной мысли (1.2): каждый сегмент раскрывает какую-то грань главной мысли. Если сегмент на неё не работает — это либо служебный фрагмент (отбросить или объединить с соседним), либо главная мысль сформулирована слишком узко (вернуться к 1.2).

#### Что такое сегмент

Сегмент = **одна крупная самостоятельная мысль автора, ради которой он отвёл существенный кусок времени**, со всеми её разворотами (концепт, демо, минусы, ещё демо). Уровень **главы курса**, а не параграфа.

Если ты не можешь сформулировать мысль сегмента одной фразой — это либо два слипшихся сегмента, либо служебный фрагмент.

**Целевой масштаб:** **5–10 сегментов на 60–90 минут**, ~10–15 минут на сегмент. Заметно больше (15+ на 90 минут) — почти всегда размельчение.

**Серийный контекст как эталон:** если есть `*_мастер.md` предыдущих частей серии — держи такой же масштаб.

#### Маркеры границы (подсказки, не критерии)

- Смена риторической функции (лекция ↔ Q&A, теория ↔ демонстрация длинного блока).
- Сигналы смены режима спикером («теперь возвращаемся…», «давайте пример», «отвечаю на вопрос»).
- Логическая ветка: ответ на «о чём этот сегмент?» требует двух разных обоснований — посмотри, не нужно ли разбить.

#### Анти-маркеры (НЕ граница)

- Смена формата внутри одной темы (теория → демо одной темы → ещё демо).
- Новая команда / фича / лайфхак, раскрывающая ту же мысль.
- Метафора, образ, оговорка.

Признак анти-маркера: формат меняется, но **главная мысль остаётся той же**.

#### Тест на укрупнение

Перед фиксацией карты — для каждой пары соседних сегментов спроси: «если объединить, получится одна развёрнутая мысль, формулируемая одной фразой?». Если да — объединить.

**Режим «с проверкой»:** показать карту пользователю, ждать «ок».

## ШАГ 2. Написание мастер-MD

Идти по сегментам по порядку. Для каждого сегмента — блок по шаблону (см. ниже). В конце — технический блок **Логическая реконструкция** (цитата `> Главная идея:` + таблица сегментов; см. отдельный раздел ниже).

### Если по ходу главная мысль уточнилась

Стилистическое уточнение (другой подбор слов, более точный глагол) — обновить молча в шапке и в блоке `> Главная идея:` Логической реконструкции (она дословная копия).

**Смысловое уточнение** (другая риторическая позиция автора, другая рамка) — остановиться, сообщить пользователю что именно уточнилось и почему, предложить новые варианты заголовка, ждать подтверждения. Без подтверждения заголовок и `**Главная мысль:**` в шапке не менять.

### Аудитория (для кого пишешь)

Взрослый с ВО, без специальной подготовки в области выступления, гуманитарного склада, со **структурным мышлением**. Замечает прыжки, оборванные мысли, нелогичные переходы. Требует раскрытия терминов простым языком или примером.

Когда пишешь — держи её в голове. Когда читаешь свой результат для самопроверки — встань на её место.

### Голос (ToV)

**Базовое:**

- Первое лицо единственного числа («я думаю», «мы разобрали»). От имени спикера.
- Живая разговорная речь, не академический текст, не деловой отчёт. Без канцеляризмов («таким образом», «следует отметить», «в рамках данного»), без пассивного залога там, где возможен активный.
- **Сохранять:** лексику и характерные обороты спикера, метафоры и образы, смысловые и эмоциональные акценты, повторения (если работают на фиксацию), все примеры, все пошаговые инструкции, все оговорки.
- **Не делать:** не переписывать в третьем лице, не заменять эмоциональные формулировки нейтральными, не «улучшать» логику, не превращать развёрнутое объяснение в набор тезисов, не сокращать ради краткости.
- **Удалять только:** паразитные слова («ээ», «ну», «как бы», «вот» как заполнитель), оговорки без смысловой нагрузки.
- **Чистить также:** **ошибки автоматического распознавания речи** — искажённые термины, имена, названия инструментов, фирменные обороты. Это технический шум, а не голос спикера. Сверять с серийным контекстом (`*_мастер.md` серии) и `tov_<серия>.md`: если в транскрипте термин написан иначе, чем уже принято в серии — это шум распознавания, чистить. Аналогично подозрительные имена собственные и техтермины — сверять и исправлять.

**Принцип сомнения:** лучше сохранить лишнее, чем потерять голос.

**Приоритеты при конфликте:** точность содержания → авторские формулировки → стилистика → читабельность. Компактность — последняя.

**Динамика:** характерные обороты конкретного спикера — из `tov_<серия>.md`.

### Объём Текста сегмента

70–90% от объёма транскрипта сегмента по знакам. Меньше — значит ужал, потерял голос. Переписать ближе к транскрипту.

### Навигация в Тексте: жирное выделение

Аудитория со структурным мышлением читает не построчно, а **глазом по жирному**. Без жирного даже точный текст превращается в простыню. Но жирное — это не «маркер интересного слова» и не «метка темы»: это **сжатая формулировка ключевой мысли**, которую несёт абзац, буллет или значение поля.

**Главный тест:** прочитать только жирное во всём сегменте сверху вниз — складывается ли канва смыслов? Если складывается — выделение работает. Если читаются разрозненные слова-метки («23 раза», «Telegram», «билборд», «частота входа») — выделение не работает, даже когда каждое слово «правильное».

**Микро-шаг «карта выделений» перед записью.** Для каждого абзаца Текста и значения `**Ключевая мысль:**` сначала мысленно формулируешь «что главное в этом абзаце» (одна-две фразы), и только затем пишешь блок целиком, расставляя жирное по этой карте. Это убирает соблазн перефразировать оригинальный текст спикера под желаемое выделение — текст спикера остаётся как был, жирное накладывается сверху. Карта не пишется в чат и не сохраняется — это внутренний микрошаг, как и сквозная цепочка (И)→(М)→(Д).

#### Текст сегмента

В каждом содержательном абзаце выделяется **сжатая формулировка его ключевой мысли** — фраза, отвечающая на вопрос «что в этом абзаце сказано». Длина определяется полнотой смысла, не лимитом: часто 4–8 слов, иногда 2–3 (если мысль помещается), иногда больше, если короче нельзя без потери смысла.

Обычно одно жирное выделение на абзац. Два — только если в абзаце реально две независимые мысли (редко).

**Не выделять:**
- связки и служебные слова: «но», «потому что», «зачем», «не нужно», «то есть», «вот», «поэтому»;
- эмоциональные оценки спикера: «классная», «круто», «вау» — это голос, не мысль;
- целый абзац или почти весь — сигнал, что мысль просится в блок `> Ключевая идея / Принцип / Метафора`, а не в жирное внутри прозы.

Это правило **дополняет** блоки `> Ключевая идея` / `> Принцип` / `> Методология` / `> Важно`, не отменяет их. Блоки — для явных авторских формулировок целиком; жирное в прозе — для сжатой мысли каждого абзаца.

#### Структурные пометки

Ярлыки шаблона (`**Ключевая мысль:**`, `**Тип:**`, `**Спикер:**`, `**Различие 1:**`, `**Кейс 1:**`, `**Ключевая идея:**` / `**Принцип:**` / `**Методология:**` внутри `> ...`-блоков) **остаются жирными** — они работают как точки фокусировки для глаза и не «расходуют» лимит на сжатую мысль абзаца. Сжатая мысль внутри значения выделяется отдельно.

#### Стереотипы для типовых блоков

В типовых блоках решение про жирное **шаблонное**, не принимается заново для каждого случая:

- В `> **Ключевая идея:** ...` / `> **Принцип:** ...` / `> **Методология:** ...` — **первая основная фраза блока выделяется жирным** как сжатая мысль; пояснение без жирного, если в нём нет отдельной независимой мысли.
- В `> **Метафора:** ...` — жирным выделяется **сама формулировка метафоры** («A — это как B»), пояснение без жирного.
- В подзаголовках `#### Различие N — параметр` / `#### Кейс N — название` — заголовок целиком работает как жирный навигационный якорь раздела; в первом содержательном абзаце под ним сжатая мысль выделяется обычным правилом.
- В блоке `> **Кейс N — название:** короткая формулировка` — структурная пометка `**Кейс N — название:**` жирная по умолчанию, плюс одно дополнительное выделение в самой формулировке (если она длиннее 5–6 слов).

#### Списки с структурой «заголовок — раскрытие»

Если буллет имеет вид `- Заголовок: пояснение` (так устроена Карта и любые подобные списки в Тексте) — **заголовок до тире/двоеточия выделяется жирным**: `- **Заголовок:** пояснение`. Это сжатая мысль буллета, и она же является навигационной точкой по списку. Дополнительное жирное внутри пояснения ставится только если в пояснении есть отдельная независимая мысль, не пересекающаяся с заголовком (редко).

#### Ключевая мысль (значение поля)

Внутри значения `**Ключевая мысль:**` (1–2 предложения сегмента) выделяется **сжатая формулировка главной мысли сегмента** — одна фраза, читающаяся самостоятельно. Не отдельные термины, а связная мысль. Если в значении две независимые мысли — две формулировки.

### Шаблон сегмента

````markdown
## Сегмент N | HH:MM:SS–HH:MM:SS | [Тема]

**Тип:** [риторическая роль: инструкция / демонстрация / тезис / разбор кейса / Q&A / отступление / комбинации через «+»]
**Спикер:** [имя]

**Ключевая мысль:** [1–2 предложения — что главное в этом сегменте]

### Карта

- **[Тезис/термин]:** [пояснение]
- **[Другой тезис]:** [пояснение]
- ...

### Текст

[Очищенный транскрипт сегмента в голосе спикера. 70–90% объёма транскрипта по знакам.

Если несколько подтем — членение через `#### подзаголовок`.

При **явных** формулировках спикера могут стоять блоки:

> **Ключевая идея:** [...]
> **Принцип:** [...]
> **Методология:** [...]
> **Лайфхак:** [...]
> **Демонстрация:** [...]
> **Важно:** [...]

Не ставить блок формально — только если спикер реально это сформулировал.]

*[Переход к следующему сегменту, 1–2 предложения в голосе спикера. Между последним сегментом и концом — переход не нужен.]*
````

### Три уровня (И)/(М)/(Д) — внутренний инструмент агента

Автор любого выступления движется между уровнями: формулирует **идею** (стратегия) → раскрывает через **методологию** (тактика) → показывает на конкретных **действиях** (операционал).

Эти три уровня — **рабочий инструмент агента**, не часть выходного файла. При формировании каждого буллета Карты мысленно классифицируй его: идея (И), метод (М) или действие (Д). В файл префикс **не пишется** — буллет идёт как `- **Тезис/термин:** пояснение`.

Зачем держать классификацию в голове: она заставляет отслеживать сквозную цепочку идея→метод→действие при чтении транскрипта и проверяет, что Карта не становится плоским списком тезисов одного уровня. Без этой мысленной проверки сегмент получается формальным.

Распределение в сегменте — по реальному характеру:

- чисто концептуальный сегмент может быть полностью идейного уровня;
- чисто инструктивный — полностью действий;
- типичный «развёрнутый» — 1–2 идеи, 1–3 метода, 3–5 действий.

**При сомнении в уровне — относить к действию (Д), не натягивать на идею/метод.** Натяжки хуже честного «это конкретный шаг».

**Сквозная цепочка как внутренний артефакт.** Перед написанием сегментов и в Самопроверке мысленно собираешь дугу всего выступления: какая идея прошивает все сегменты, как они движутся по уровням И→М→Д, все ли раскрывают Главную мысль из шапки. В файл эта аналитика не выводится — Главная мысль шапки и `> Главная идея:` в Логической реконструкции фиксируют её одной формулировкой.

### Вставка промптов

Если в сегменте спикер показывает, зачитывает промпт или предлагает заскринить — промпт вставляется в Текст **дословно**, отдельным блоком. Это применимо к промптам из любого источника: скрины, презентация, надиктованный голосом, найденный в транскрипте.

**Источник приоритета (от точного к наименее точному):**

1. Скрин промпта (распознан в ШАГ 0).
2. Презентация (если промпт есть в слайдах).
3. Транскрипт (только если двух предыдущих нет).

Если есть скрин или презентация — текст берётся из них. Транскрипт в этом случае служит только для определения **места вставки** и **названия промпта** (как его называет спикер).

**Дословность.** Сохранять **всё**: нумерацию, маркеры списков, отступы, переносы строк, регистр, пунктуацию, кавычки, спецсимволы, переменные в `[квадратных скобках]` или `{фигурных}`. Не «причёсывать», не сокращать, не объединять строки. Если в источнике пустая строка между блоками — она остаётся.

**Формат блока:**

````markdown
> **Промпт «[название как у спикера]»:**

```
[текст промпта дословно из источника]
```
````

Метка-blockquote — для единообразия с остальными блоками сегмента (`> Ключевая идея`, `> Методология` и т.п.). Fenced code block — потому что внутри `>` markdown мнёт переносы и непредсказуемо рендерит вложенные списки, а в code block структура сохраняется точно.

Если промптов в сегменте несколько — несколько таких блоков подряд, каждый со своим названием.

### Когда использовать `> Методология`

Автор раскрывает идею через **пошаговый алгоритм** (3+ шагов с логической последовательностью), и эту последовательность важно зафиксировать как самостоятельный артефакт, а не растворить в Тексте. Часто **целое выступление = одна методология** (например, лекция вида «как создать X» — это методология создания X). В таких случаях блок ставится один на сегмент и собирает её ядро в нумерованный список.

Карта показывает **структуру выступления** (где в материале лежит что). Блок `> Методология` показывает **сам алгоритм** (что и в каком порядке делать). Это разные сущности — Карта не заменяет Методологию.

### Дописать прозу «взгляд сверху» (если блок 1.3 был открыт)

Выполняется в самом конце ШАГ 2, после того как **все сегменты написаны**.

Вернуться к началу мастер-MD, в раздел `## Замысел и маршрут`, и **дописать 4–6 коротких абзацев прозы** перед опорной структурой. К этому моменту перед глазами уже все заголовки сегментов, тексты, главная мысль — проза пишется ретроспективно, с полной картиной.

**Содержание прозы:**
- О чём этот урок (1 абзац).
- Что автор хочет донести / какая риторическая позиция (1 абзац).
- Какая внутри логика, как этапы связаны (1–2 абзаца).
- Есть ли поворот / акцент / что не очевидно (опционально, 1 абзац).

**Простой язык.** Без «риторической дуги», «глубинного зачем», «фундамента, который держит». Тест — прочитать вслух: звучит как нормальная речь?

**Жирное = сжатая мысль абзаца.** Не выделять цвет/смысл вообще — только ключевую формулировку, чтобы при сканировании сверху вниз глаз цеплялся за неё.

**Опорную структуру при необходимости подправить:** если за время написания сегментов формулировки этапов уточнились, привести список пунктов в соответствие с финальными заголовками сегментов.

Если блок 1.3 **не открывался** (нет нити) — этот под-этап пропускается.

### Логическая реконструкция (технический минимум)

Раздел остаётся в файле **только как технический служебный блок** для Слоя 2 (виджет берёт из него содержимое первого экрана). Аналитика и проза в нём не пишутся.

```markdown
## Логическая реконструкция

> **Главная идея:** [одна формулировка — дословная копия `**Главная мысль:**` из шапки]

| --- | --- | --- |
| 1 | [роль] | [ход]                                                                  |
```

- **Прозы в реконструкции нет.** Развёрнутая аналитика «как устроена аргументация автора» — это **внутренняя работа агента** (см. раздел «Три уровня (И)/(М)/(Д)»), а не текст в файле. Для человека-читателя весь смысл выступления уже передан Главной мыслью шапки и шестью сегментами.
- Если виджет в дальнейшем кастомизируется через Слой 3 — первый экран собирается заново по сегментам, эта реконструкция там не используется.

**Шаблон раздела «Замысел и маршрут» (вставляется сразу после шапки, если блок 1.3 был открыт):**

```markdown
[4–6 коротких абзацев прозы «взгляд сверху» — дописываются в конце ШАГ 2.

**Этапы:**

1. **Этап 1 — <глагол>: <суть>** — почему отсюда начинаем / что даёт.
```

Имя маркера опорной структуры зависит от формы:

## ШАГ 3. Самопроверка

После того как мастер-MD собран, **до сохранения файла** — перечитай свой результат глазами Аудитории.

Это видимый блок в чате. **В сохраняемый файл не попадает.**

### Формат

```markdown
### Самопроверка — глазами Аудитории

Я только что прослушал курс и читаю получившееся как взрослый человек
с высшим образованием, без специальной подготовки в области, гуманитарного
склада, но со структурным мышлением.

[2–4 абзаца свободной рефлексии в первом лице. Что сложилось, что осталось
рваным, где запутался, понятна ли логика автора, складывается ли целостная
картина, не «прыгает» ли изложение. Со ссылками на конкретные сегменты,
абзацы, заголовки.]

**Что хочу поправить:**

- [конкретная правка с указанием места]
- (или: «Менять ничего не нужно.»)
```

### Анти-саботаж

- Самопроверка пишется в **первом лице** («я понял», «я запутался»), не в третьем («читатель поймёт»). Третье лицо — признак отписки, не чтения.
- Обязательны ссылки на **конкретные места** (номера сегментов, цитаты, заголовки). Без конкретики блок не засчитывается.
- Правки конкретные: «между сегментами 4 и 5 переход висит в пустоте — переписать так-то», не «уточнить переходы».

### Ориентиры при чтении (не для отчёта)

- Складывается ли цельная история, или это набор разрозненных сегментов?
- Сегменты раскрывают главную мысль из шапки, или есть «лишние», которые на неё не работают?
- **Сквозная цепочка (И)→(М)→(Д) собирается мысленно** — все ли сегменты раскрывают Главную мысль из шапки, видно ли движение идея→метод→действие?
- Понятна ли логика переходов между сегментами?
- Голос спикера сохранён, или где-то ушёл в нейтральный учебник?
- Технические термины раскрыты, или предполагается, что Аудитория сама поймёт?
- Жирное в Тексте — это **сжатая мысль каждого абзаца**? Тест: прочитать только жирное сверху вниз — складывается ли канва смыслов, или это разрозненные слова-метки?
- В Ключевой мысли выделена сжатая формулировка главной мысли сегмента, не отдельные термины?
- В Карте структура `- **Заголовок:** пояснение` выдержана; нет лишнего жирного внутри пояснений?

### Действие при находках

- Локальная правка (переход, формулировка, выделение) — правишь мастер-MD на месте.
- Серьёзный провал, требующий переписывания целого блока Текст — переписать или (если уверенности нет) поставить в начало сегмента метку `⚠️ требует проверки` и явно зафиксировать в рефлексии что и почему.

## ШАГ 4. Сохранение

### Куда сохранять

- **По умолчанию** — сохранять в рабочую папку серии воркспейса (`konspekts/<серия>/`), где лежит исходник и предыдущие уроки. Имя файла — `OUT_[название]_мастер.md` (префикс `OUT_` как в эталоне серии). Материалы серии (`.srt`, тайминги, `tov_<серия>.md`, мастера, виджеты) лежат в одной папке.

- **Не дублировать** в обе локации — лишний файл.

### Режим работы

**Режим «с проверкой»:** показать содержимое пользователю, ждать «ок», затем сохранить.

**Автоматический режим:** сохранить сразу, отчитаться одной строкой:

```
Мастер-MD готов: [путь]/[название]_мастер.md (N сегментов[, X сегментов ⚠️ если есть]).
```

- **Не использовать TodoWrite** — пайплайн линейный, прогресс виден из текста сообщений.

## Ручная нарезка (`/konspekt split`)

Когда пользователь пишет `/konspekt split <файл> [--target-min N]` — это **утилита**, не пайплайн мастер-MD: скрипт только режет транскрипт на части, обработки в мастер-MD нет.

Отличие от авторезки (ШАГ 0.3): запускается **по явной команде пользователя при любой длительности**, и размер фрагмента задаёт пользователь через `--target-min` (по умолчанию 90). Допуск +10 мин действует и здесь: при `--target-min 30` файл ≤ 40 мин не режется.

**Алгоритм — тот же, что в ШАГ 0.3:**

1. `python "$HOME/.claude/skills/konspekt/split_transcript.py" info "<файл>" --target-min N` — сколько частей.
2. `... windows "<файл>" --target-min N` — окна вокруг целевых точек.
3. Выбрать швы по правилу из вывода (вперёд 5–10 мин → иначе строго назад; не резать посреди темы).
4. `... split "<файл>" --at <шов1>,<шов2>,...` — создаёт `<имя>_ч1.txt … _чN.txt`.
5. Отчитаться путями к частям. В мастер-MD не обрабатывать (если пользователь не попросил отдельно).

## Режим `preview`

Когда пользователь пишет `/konspekt preview <путь или YouTube-URL>` — это **отдельный режим**, не часть пайплайна мастер-MD.

**Алгоритм:**

1. Прочитать `preview.md`.
