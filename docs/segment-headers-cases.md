# База кейсов: заголовки и границы сегментов

> **Назначение.** Корпус реальных правок `было → стало → нарушенное правило` для дообучения
> скилла `/konspekt` на этапе сегментации и создания заголовков (режим master, ШАГ 1.4).
> Это **evidence** — материал для блока контраста в ШАГ 1.4. Аналитический разбор корпуса —
> в `docs/segment-headers-analysis.md`; контекст задачи — в `docs/task-segmentation-headers-retraining.md`.
>
> **Как сюда попадают записи.** Автоматически: в конце master-сессии, где пользователь
> правил заголовки или границы, агент дописывает пары сюда (правило в `SKILL.md`, ШАГ 4).
> Можно дописать и вручную по команде «запиши в базу кейсов».

## Коды паттернов — заголовки

| Код | Паттерн ошибки |
|---|---|
| P1 | Назывной / технический заголовок («Введение:…», «Демонстрация:…») вместо глагола процесса |
| P2 | Антитеза «не А, а Б» в заголовке |
| P5 | Не ориентирован на читателя / на пользу |
| P6 | Жирным весь заголовок (надо только часть до двоеточия) |
| P7 | Ответ в заголовке вместо вопроса (для Q&A/разборов) |
| P8 | Слишком длинный / развёрнутый / непонятный |
| P9 | Нет преемственности — не отражает единый процесс серии (для лекций-методологий) |
| P10 | «Чёрный ящик»: длинный сегмент — одна абстрактная фраза, непонятно что внутри |
| P11 | Пестрит терминами, нечитабелен |
| P12 | Первое лицо (я/мы) в заголовке Q&A-вставки. Для совместных шагов процесса 1 лицо мн.ч. уместно («разбираем/создаём» — зритель идёт с ведущим), но действие «отвечать на вопросы из чата» принадлежит только ведущему: «мы» ложно (зритель не участвует), «я» путается с голосом конспекта. Решение — именная группа без лица и без глагола-действия: «Пауза на вопросы — <суть вопросов>». Смена формы глагол→имя сама помечает выпадение из процесса |
| P13 | Служебный термин методологии скилла протёк в заголовок сегмента («Рамка — …», «Резюме — …», «Замысел — …»). Эти маркеры живут только в блоке «Замысел и маршрут» (опорная структура), в заголовке сегмента их видит читатель и не понимает — это внутренний жаргон агента, не содержание. Решение: крайние сегменты (вводный/итоговый) называть содержательно с позиции читателя, как средние. «Этап N» — исключение: это пользовательски прозрачный маркер процесса, серия его использует |
| P14 | Ложная лестница: процессный маркер «Этап N» навешен на **параллельные альтернативы**, которые выбирают по ситуации, а не делают по очереди. Возникает, когда серия использовала «Этап N» для реально линейного how-to, а текущий урок — список тактик/способов; перенос того же маркера 1:1 создаёт у читателя ложное «делай по порядку». Это инверсия «чужой структуры» (агент сам натянул лестницу, которой в материале нет). Решение: маркер последовательности — только на реально последовательные шаги; для набора альтернатив брать авторский маркер выбора («Способ N») или смысловые заголовки по граням, рамку/итог — обычными смысловыми заголовками. Преемственность серии = тот же стиль (глагол процесса/польза), а не тот же ярлык при другой форме материала |
| P15 | «Этап» присвоен блоку, который идёт **после** того, как заявленный автором результат урока уже достигнут (кода / доп. примеры / анонс следующего дня) — нумерация тянется по инерции дальше цепочки, хотя цель уже выполнена. Проверка: сформулировать явный «результат», который автор анонсировал в начале (часто прямой цитатой — «результатом сегодняшнего дня будет…»), и остановить нумерацию этапов на сегменте, где он достигнут. Решение: всё, что идёт после результата — заголовок без «Этап N», обычный смысловой |
| P16 | Плоская перечислительная рамка для связанных сегментов: набор сегментов помечен нейтральным счётным ярлыком («Лайфхак N», «Приём N», «Фишка N»), который подаёт их как разрозненный список, хотя в материале есть **конструктивная связь** — один сегмент служит основанием для остальных. Отличие от P14: там ошибка в ложной *последовательности*, здесь — в потерянном *единстве* (перечисление вместо конструкции). Признак: заказчик говорит «создаёт ощущение разрозненности». Решение: найти несущую связь (часто у автора уже есть метафора — напр. «фундамент»/«база», которую он повторяет) и отразить её в метках через роли (например «Фундамент — …» + «Опора N — …»), а не плоским списком; единство дополнительно проговорить прозой в «Замысел и маршрут». Преемственность серии = тот же стиль «<роль/маркер> N — <глагол>: <суть>», не обязательно тот же ярлык, что в прошлых днях |

| P17 | Нумерация «Этап N» протянута сквозь **разнородные пласты** одной части. Отличие от P14 (лестница навешена на параллельные альтернативы): здесь материал реально распадается на два и более блока **разной природы** — например, вставная лекция о карьере и последующая практическая настройка, — а сквозная нумерация склеивает их в ложный единый маршрут. Признаки, что нити нет: автор идёт по **нумерованному оглавлению** тем («переходим к пункту три… а теперь к десятому»), а не по шагам, где каждый стоит на предыдущем; внутри части лежит блок с **собственной подводкой и финалом**, после которого автор говорит «а теперь **вернёмся** к…»; обзор источника делит материал там же и даёт блокам разную рекомендацию к просмотру. Решение: тест на нить (ШАГ 1.3) проходить не для части целиком, а проверять на разнородные пласты; при двух и более пластах нумерацию не вводить, заголовки — по граням, сами пласты обозначить прозой в «Замысел и маршрут» |
| P18 | Хвост-перечисление в заголовке дублирует Карту. Заголовок смысловой и по остальным пунктам чек-листа проходит, но к нему через двоеточие прицеплен состав сегмента («…: подписка, где запускать, первые запросы»), который слово в слово раскрыт ниже в Карте. Решение: хвост оставлять, только если без него сегмент читается как чёрный ящик (обычно длинные, от ~10 мин, где перечисление и есть содержание — «Три навыка масштаба: скорость итераций, свой Джарвис, второй источник дохода»); если суть ясна и без хвоста — отрезать. Два прохода по каждому заголовку: сначала «понятно ли, что внутри», затем «не пересказал ли я Карту» |
| P19 | Термин спикера вынесен в заголовок там, где аудитория его ещё не знает («`CLAUDE.md` как системный промпт»). Заголовок читают до текста, поэтому в нём нужен смысл, а не словарь автора: «системный промпт проекта» → «память проекта». Сам термин никуда не девается — он раскрывается в Карте и Тексте, где для него уже есть контекст |

## Коды паттернов — границы

| Код | Паттерн ошибки |
|---|---|
| B1 | Размельчение (слишком много мелких сегментов) |
| B2 | Переукрупнение (слишком крупные, теряется что внутри) |
| B3 | Дисбаланс (рядом мелкие и крупные без смысловой причины) |
| B4 | Q&A / авторские вставки слиты с содержательными сегментами |
| B5 | Разнотемное склеено в один сегмент |
| B6 | Гранулярность сопроводилки протекла в сегментацию: сегменты нарезаны по слайдам/пунктам презентации (или иной детальной опоры), а не по смысловым этапам. Признак-маска — подозрительно ровные по длительности куски. Лечение: сегментировать по этапам метода (1.3), презентацию использовать как источник формулировок и промптов, а её дробление слайдов — игнорировать как навигацию спикера, не как карту глав |
