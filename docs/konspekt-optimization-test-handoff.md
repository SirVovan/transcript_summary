## Известные риски

### 1. Парсер SRT в preprocessor.py

При прогоне `python .claude/skills/konspekt/preprocessor.py head "transcripts/Урок 2.srt"` команда работает, но в выводе видны остаточные фрагменты SRT-таймштампов (`,000 --> 00:00:30,000`). `parse_transcript_lines` рассчитан на формат с разметкой `[HH:MM:SS]`, а не на SRT.

**Что это значит для теста:**
- Команда `head` отрабатывает без исключений и возвращает текст транскрипта.
- Бригадир, извлекая ToV из этого вывода, увидит лишний шум — но текст для извлечения характерных оборотов всё равно читаем.
- На сегментацию это влияние не оказывает (Ф1 работает с чанками, а не с head-выводом).

**Если ToV получается мусорным:**
- Вариант A: предварительно конвертировать SRT → TXT (вырезать таймштамповые строки).
- Вариант B: доработать `parse_transcript_lines` в `preprocessor.py` для распознавания SRT-формата.

### 2. layer2_widget.md ожидает `## Траектория`

Файл `.claude/skills/konspekt/layer2_widget.md` (виджет-генератор, Слой 2) использует раздел `## Траектория` мастер-MD как источник данных для `trajectory`. После заморозки Траектории этот раздел в мастер-MD не появляется. Виджет-генератор будет получать `trajectory: null`.

**Это побочный эффект заморозки, вне рамок плана #2026-05-17.** Решение — следующая итерация:
- Либо разморозить Траекторию.
- Либо обновить виджет-генератор (брать данные из Логической реконструкции).

### 3. ToV-файл серии для нового транскрипта

При первом прогоне `transcripts/tov_<серия>.md` для серии «Урок 2» не существует — бригадир должен пойти по второй ветке (`preprocessor.py head` → извлечь ToV → сохранить файл). Проверить, что файл реально создаётся в `transcripts/`.
