Сегмент 8 | 01:56:57–02:02:36 | Зачем MCP: проблема API-вызовов и единый протокол
Риторическая роль: тезис
Чанк: 1

Подключать внешние сервисы можно «хардкодом» через HTTP/API, но придётся вручную описать каждый endpoint, структуру данных и доступы — у каждого сервиса свои.
Для одной только Google-таблицы пришлось бы прописывать десятки действий (создать лист, добавить строку, форматировать) — это долго и тяжело поддерживать.
MCP (Model Context Protocol) — единый протокол, через который любой AI-агент подключается к внешним сервисам и получает описание их инструментов «из коробки».
Метафора спикера: агент — это компьютер, MCP — USB-хаб с описанием протоколов, через который подключаются «внешние устройства»-сервисы.

Сегмент 14 | 02:29:27–02:34:39 | Архитектура router и маршрутизация запросов
Риторическая роль: инструкция
Чанк: 1

При любом запуске Claude Code сначала читает CLAUDE.md, где описаны режимы: прямой вызов конкретного агента или работа через router.
Router (.claude/agents/router) — «тимлид», на которого основная инструкция переадресует пользовательский запрос; он сам определяет, какой субагент нужен.
Папка runtime делится на Outputs (готовые отчёты md/HTML/PDF) и Shared (технические данные JSON, которыми обмениваются агенты).
Внутри router-а — Chain of Thought-инструкция: классифицировать запрос, понять, к какому агенту он относится, нужна ли цепочка, какие данные передать.
Таблица маршрутизации привязывает ключевые слова к агентам: «найди/сравни/исследуй» → DeepResearch, «собери с сайта» → Parser, «новости» → News Digest, «проанализируй документ» → Doc Analyzer и т.д.; составные запросы складываются в цепочки.

Сегмент 3 | 01:56:57–02:19:06 | MCP: единый протокол подключения внешних сервисов
Риторическая роль: концепт + инструкция + демонстрация
Чанк: 1

Проблема: подключать сервисы через сырые API-вызовы — значит вручную описывать агенту каждый endpoint, структуру данных и доступы; для одной только Google-таблицы — десятки действий.
Решение: MCP (Model Context Protocol) — единый протокол, через который любой AI-агент подключается к внешним сервисам и получает описание их инструментов «из коробки». Метафора спикера: агент — компьютер, MCP — USB-хаб.
Установка: в Smithery в карточке сервиса видно список инструментов (у Google Sheets их 38); два способа — вставить промт в Claude Code (агент сам поставит) или CLI-команду в терминал. Демо: первый вызов открывает авторизацию через Smithery; Claude Code создаёт пустую таблицу, заполняет данными и отдельным промтом «делает красиво» (шрифты, заголовки, цвета).
Команда /mcp показывает все установленные MCP (в расширении список неполный — нужен терминал).
Главный минус: /context показывает, что одна только Google-таблица — порядка 2000 токенов; 10 MCP — это ~20 000 токенов в каждом запуске. Если сервис нужен не каждый день, разумнее завернуть его в скилл с обычными HTTP-запросами — контекст подгружается только при реальном вызове.
Лайфхак: попросить Claude Code через официальный скилл Skill Creator (от Anthropic) превратить установленный MCP в скилл — он сам соберёт SKILL.md и tool reference. Спикер считает MCP частично устаревающим из-за нагрузки на контекст.
