# Оптимизация скилла /konspekt — план для отдельной сессии

**Дата фиксации:** 2026-05-23
**Контекст:** ретроспектива после длинной перегенерации мастер-MD М2-У10-1 (правка правила жирного). Замедление вылезло на двух местах — большой объём мысленных решений на каждом абзаце и дублирующиеся разделы в SKILL.md. Ниже — системные правки, которые дают эффект на **каждом будущем конспекте**, а не только на разовой перегенерации.

**Статус (2026-05-23):** правки **C, A, D — применены к SKILL.md**. Правка **B (сжать SKILL.md)** — отложена, согласно рекомендации внизу документа (не раньше чем через 2–3 сессии применения нового правила жирного).

---

## Что НЕ делать системно (зафиксировано для ясности)

- Применять правило с первой генерации — это следствие сегодняшней работы, не правка скилла. На новых конспектах перегенерации обычно нет.
- MultiEdit при правках разметки — общая дисциплина инструментов, не правило `/konspekt`.
- Пропускать «план предыдущей сессии» в начале — зависит от того, самодостаточен ли handoff. Решение по ситуации.

---

## Правки, дающие эффект на каждой сессии

### A. Стереотипные правила выделения в типовых блоках

**Где:** `.claude/skills/konspekt/SKILL.md`, раздел «Навигация в Тексте» → новый подраздел «Стереотипы для типовых блоков».

**Проблема.** В любом мастер-MD есть ~10–15 блоков формы `> **Ключевая идея:**`, `> **Принцип:**`, `> **Метафора:**`, `> **Методология:**`, а также подзаголовки `#### Различие N`, `#### Кейс N`. Для каждого агент сейчас принимает решение про жирное «с нуля». Решение почти всегда одинаковое — это лишняя мысленная работа.

**Что добавить (черновик):**

> **Стереотипы для типовых блоков.** Для следующих структур решение про жирное **шаблонное**, не принимается заново:
>
> - В `> **Ключевая идея:** ...` / `> **Принцип:** ...` / `> **Методология:** ...` — **первая основная фраза блока выделяется жирным** как сжатая мысль; остальное пояснение без жирного, если в нём нет отдельной независимой мысли.
> - В `> **Метафора:** ...` — жирным выделяется **сама формулировка метафоры** («A — это как B»), пояснение без жирного.
> - В подзаголовках `#### Различие N — параметр` / `#### Кейс N — название` — заголовок целиком работает как жирный навигационный якорь раздела, в первом содержательном абзаце под ним — сжатая мысль обычным правилом.
> - В блоке `> **Кейс N — название:** короткая формулировка` — структурная пометка `**Кейс N — название:**` жирная по умолчанию, плюс одно дополнительное выделение в самой формулировке (если она длиннее 5–6 слов).

**Эффект:** на каждом мастер-MD — ~10–15 блоков с заранее решённым правилом вместо мысленной работы каждый раз.

### B. Сжать SKILL.md

**Где:** `.claude/skills/konspekt/SKILL.md` в целом.

**Проблема.** Файл ~390 строк, читается целиком на каждой сессии (~10K токенов входа). За последние сессии накопились дублирующие куски:

- Раздел «Три уровня (И)/(М)/(Д) — внутренний инструмент агента» (строки ~221–237) и абзац «Сквозная цепочка как внутренний артефакт» внутри него (~237) — одна тема, поданная дважды.
- Раздел «Навигация в Тексте» (после правки 2026-05-23) разросся до ~50 строк — можно сжать до ~30 без потери смысла после стабилизации правила (через 2–3 сессии применения).
- Шаг 0 «Сопроводительные материалы» (строки ~40–48) — раздел «Презентация» + «Скрины промптов» можно объединить через общий принцип «прочитать до ШАГ 1, дословное распознавание».

**Цель ужать до ~280–300 строк** без потери смысла.

**Эффект:** ~3–5K входных токенов сэкономлено на **каждой** сессии /konspekt (постоянная экономия).

**Когда делать:** не раньше чем через 2–3 сессии применения нового правила жирного — чтобы убедиться, что оно работает и не требует расширений.

### C. Серийный контекст — читать выборочно

**Где:** `.claude/skills/konspekt/SKILL.md`, ШАГ 0, пункт 1 «Серийный контекст».

**Проблема.** Сейчас инструкция:

> «Серийный контекст: проверить `transcripts/` на `*_мастер.md` той же серии. Если есть — прочитать, использовать как эталон масштаба сегментации и стиля.»

На длинных сериях (курс Ледовских — десятки уроков по 20–30 минут, каждый мастер-MD ~10–15K токенов) полное чтение всех `*_мастер.md` серии — десятки тысяч входных токенов на сессию. Для калибровки масштаба сегментации этого **не нужно**.

**Что переписать:**

> «Серийный контекст: проверить `transcripts/` на `*_мастер.md` той же серии. Если есть — **прочитать шапку + Карты + Ключевые мысли** последних 2–3 уроков серии (без Текстов сегментов). Этого достаточно для эталона масштаба сегментации и калибровки голоса. Полные Тексты читать только если возникает конкретный вопрос — например, как спикер раскрывал термин X в прошлом уроке.»

**Эффект:** на длинных сериях — экономия до 30K входных токенов на каждую сессию. Самый большой системный выигрыш по токенам.

---

### D. Микро-шаг «карта выделений» в ШАГ 2

**Где:** `.claude/skills/konspekt/SKILL.md`, ШАГ 2, перед или внутри раздела «Шаблон сегмента».

**Проблема.** На сегодняшней перегенерации главный источник откатов — соблазн перефразировать оригинальный текст спикера под желаемое выделение. Тратится время на «передумал → вернул как было». Если **сначала** мысленно зафиксировать жирное, а **потом** записать абзац целиком — соблазна нет.

**Что добавить (черновик):**

> **Перед записью каждого сегмента — короткая мысленная карта выделений.** Для каждого абзаца Текста и значения `**Ключевая мысль:**` сначала формулируешь «что главное в этом абзаце» (одна-две фразы), и только затем пишешь блок целиком, расставляя жирное по этой карте. Это убирает соблазн перефразировать оригинальный текст спикера под желаемое выделение — текст спикера остаётся как был, жирное накладывается сверху.
>
> Карта не пишется в чат и не сохраняется — это внутренний микрошаг, как и сквозная цепочка (И)→(М)→(Д).

**Эффект:** меньше переделок и токенов на «писать → отменять → переписывать» внутри ШАГ 2.

## Приоритизация

| # | Правка | Эффект на сессию | Трудоёмкость |
|---|---|---|---|
| C | Серийный контекст выборочно | до 30K входных токенов (на длинных сериях) | мало (1 строка в ШАГ 0) |
| A | Стереотипы для типовых блоков | ~10–15 решений вместо думанья | мало (10–12 строк в SKILL) |
| D | Микро-шаг карта выделений | меньше откатов в ШАГ 2 | мало (5–6 строк в ШАГ 2) |
| B | Сжать SKILL.md | ~3–5K входных токенов | средне (час работы) |

**Рекомендуемый порядок:** C → A → D → B. Первые три можно сделать в одной короткой сессии (10–15 минут работы). B стоит отложить ещё на 2–3 сессии применения нового правила жирного — чтобы было видно, какие куски действительно устаканились.

---

## Verification (когда правки применены)

1. **C.** Открыть первый конспект новой серии и убедиться, что агент прочитал только шапки/Карты/Ключевые мысли соседних уроков, а не Тексты целиком.
2. **A.** На следующем мастер-MD проверить, что в `> ...`-блоках жирное расставлено по стереотипу (первая фраза, не отдельные слова).
3. **D.** В чате сессии не должно быть откатов «писать → переписать абзац», если правило применяется.
4. **B.** После сжатия — прогнать парсер на нескольких старых мастер-MD и убедиться, что ничего не сломалось (правила в SKILL.md не влияют на парсер, но сверка структуры шаблона сегмента важна).
