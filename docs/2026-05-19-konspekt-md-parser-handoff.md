# Сопроводительная записка для нового диалога

**Тема диалога:** рефакторинг скилла `/konspekt` — научить генератор виджета читать мастер-MD напрямую, без промежуточного JSON.

## Контекст

Сейчас Слой 2 (виджет) работает в два шага:

1. Я как агент собираю промежуточный JSON из мастер-MD (вручную или через одноразовый Python-builder, который пишу с нуля каждый раз).
2. `widget_generator.py` принимает JSON и выдаёт HTML.

Шаг 1 — это лишний «переводчик»: я каждый раз вручную переношу содержание мастер-MD в код, могу ошибиться, забыть жирное, перепутать метку блока. На один виджет уходит ~15 минут, основная часть — builder.

**Цель рефакторинга:** убрать шаг 1. Генератор учится принимать мастер-MD напрямую: `python widget_generator.py master.md` → HTML. JSON-режим остаётся как резервный (если захочется тонко допилить виджет руками без правки мастер-MD).

**Что даст:**
- Время на виджет: с ~15 минут до ~3 минут.
- Мастер-MD становится единственным источником правды. Поправил MD → пересобрал виджет одной командой. Сейчас правки мастер-MD молча устаревают виджет.
- Меньше моих ошибок: парсер применяет правила одинаково всегда.

## Что нужно сделать

Расширить `widget_generator.py` (или вынести парсер в отдельный модуль) так, чтобы он принимал мастер-MD и парсил его в ту же внутреннюю структуру, которую сейчас даёт JSON. Дальше существующая логика рендера HTML работает без изменений.

**Что парсер должен распознать в мастер-MD:**

- **Шапка файла:** `# Название`, `**Спикер:** ...`, `**Длительность:** ...`, `**Профиль:** ...`.
- **Раздел `## Логическая реконструкция`:** проза (с `**жирным**`) + блок `> **Главная идея:** ...` + таблица.
- **Раздел `## Сегмент N | HH:MM:SS–HH:MM:SS | Тема`** × N, внутри:
  - `**Тип:**` → определить виджетный тип сегмента (`concept` / `method` / `demo`) по таблице из `layer2_widget.md`.
  - `**Ключевая мысль:** ...` → префикс для body.
  - `### Карта` → буллеты `- **(И/М/Д)** ...` → правая колонка (insight-карточки).
  - `### Текст` → абзацы, `#### подзаголовки`, `**жирное**`, `*курсив*`, блоки `> **Метка:** ...` (одно- и многострочные с `> 1. ...`), промпт-блоки `> **Промпт «…»:**` + fenced ` ``` ` (с моноширинным `.pr-block` и кнопкой «копировать»).
  - Курсив-переход `*...*` в конце сегмента — как обычный курсив.

**Цвета блоков и шаблоны HTML** уже описаны в `.claude/skills/konspekt/layer2_widget.md` (таблица меток → bg/border, шаблон `.pr-block`). Парсер их применяет, новых правил вводить не надо.

**id промптов** — сквозные по виджету, `p1`, `p2`, ..., в порядке встречи в мастер-MD.

## Решения, принятые до старта

- **JSON-режим оставляем** как резервный путь. Генератор определяет формат по расширению (`.md` → парсить, `.json` → как раньше).
- **Если структура мастер-MD изменится** (новый раздел, переименованный заголовок) — парсер падает с понятной ошибкой («ожидал `### Карта`, нашёл `### Структура` в сегменте 2»). Никаких молчаливых багов.
- **Парсер не делает редактуру.** Он только переносит контент. Если в мастер-MD ошибка — она попадает в виджет один-в-один.
- **Тесты на регрессию обязательны.** Хотя бы один «золотой» мастер-MD прогоняется парсером, результат сравнивается с эталонным HTML. См. ниже.

## Где лежат файлы

`.claude/skills/konspekt/`:

## Эталонный тест (золотой)

Сегодня собран свежий виджет — он и есть критерий «не сломал»:

- Мастер-MD: `transcripts/Вайбкодинг. Модуль 1. Урок 2. Пошаговый алгоритм + личный проект_мастер.md` — 3 сегмента, 6 промптов из презентации, блоки `> Важно`, `> Пример`, `> Принцип`, `> Методология`, `> Критерии`, `> Шаг 4. Финальная формулировка`, `> Пример декомпозиции`, заголовки `#### Шаг N`, курсивы-переходы.
- Эталонный HTML: `transcripts/Виджет — Вайбкодинг. Модуль 1. Урок 2.html` — корректно рендерится в браузере, JS syntax OK.
- Эталонный JSON: `transcripts/Виджет — Вайбкодинг. Модуль 1. Урок 2.json` — то, во что парсер должен превратить мастер-MD (близко, не обязательно байт-в-байт).

**Критерий приёмки:** `python widget_generator.py "transcripts/Вайбкодинг. Модуль 1. Урок 2. Пошаговый алгоритм + личный проект_мастер.md"` → HTML визуально идентичен эталонному при открытии в браузере (5 экранов: Реконструкция + 3 сегмента, все 6 промптов с кнопками «копировать», все цветные блоки на месте, переходы по табам работают).

## Подводные камни

1. **Многострочные blockquote-блоки.** Markdown-парсеры по-разному обходятся с `> 1. ...\n> 2. ...` — нужно склеивать в один HTML-`<div>` со вложенным `<ol>`. Не превращать каждую строку в отдельный блок.
2. **Промпт-блок — это две сущности подряд:** blockquote с меткой + пустая строка + fenced code. Их надо склеивать в один `.pr-block`. Метка идёт в `.pr-label`, тело fenced — в `.pr-text` (с экранированием HTML, переносы строк сохраняются через `white-space:pre-wrap`).
3. **Метка блока, которой нет в таблице.** Если встретится `> **Шпаргалка:**` или другое не из таблицы `layer2_widget.md` — парсер должен либо выбрать дефолт по эвристике (см. правила в `layer2_widget.md`), либо предупредить. Не падать.
4. **Жирное и курсив в Карте.** Буллет `- **(И)** Без чёткой идеи...` — первое `**...**` это метка уровня, остальное — обычный текст с возможным внутренним `**жирным**`. Не схватить случайно метку как «весь буллет».
5. **Курсив-перехода в конце сегмента** — отличить от обычного `*слово*` внутри прозы. Эвристика: целиком курсивный абзац после последнего блока сегмента.
6. **`### Текст` может быть пустым в подразделе** — `#### Шаг 5. Реализация (13:27–14:29)` идёт сразу за прошлым h4, между ними просто абзацы. Парсер не должен теряться.
