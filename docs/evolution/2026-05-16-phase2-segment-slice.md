# 2026-05-16 — Фаза 2: отрезок сегмента вместо целого чанка

## Что изменилось

Субагент Фазы 2 теперь получает `[CHUNK_сегмента]` — только тот отрезок транскрипта, который соответствует его сегменту, а не чанк целиком.

Новая команда: `preprocessor.py slice <чанк> --from HH:MM:SS --to HH:MM:SS` печатает строки чанка в диапазоне таймштампов. Перед запуском writer'ов из чистовой карты прогоняется `slice` для каждого сегмента, результат подаётся как `[CHUNK_сегмента]`.

Фаза 1 без изменений — там агент по-прежнему получает чанк целиком (ищет границы сегментов).

## Почему так

Каждый writer получал полный `[CHUNK]` (~12K токенов, ~60 мин транскрипта), хотя писал один сегмент (~12 мин). На лекции 2 ч с 10 сегментами это ~120K токенов суммарно только на `[CHUNK]`, бóльшая часть — данные за пределами сегмента.

Сравнение по токенам (база: 2-часовая лекция, 10 сегментов):

| Схема | Input Фазы 2 | Экономия | Wall-clock | Риски |
|---|---:|---:|---|---|
| Текущая (чанк целиком) | 164 000 | — | 1× | — |
| **A (отрезок сегмента)** | **68 000** | **~58%** | 1× | — |
| B (1 агент = чанк, пишет все свои сегменты) | 33 600 | ~80% | 4–5× медленнее | Деградация в длинном output, слабее самопроверка, retry в 5–6× дороже |

Вариант B экономит больше, но за счёт качества: длинный output деградирует, самопроверка слабее, retry дороже. Вариант C (чанки 40 мин вместо 60) для A даёт 0 экономии (размер `[CHUNK_сегмента]` определяется сегментом) и добавляет накладные на нарезку — отвергнут.

Остаток накладных (`subagent_phase2.md`, NAV MAP, TOV SPEC) всё ещё дублируется M раз, но единственный путь к нему — Вариант B с его минусами. Не стоит жертвовать качеством ради дополнительных ~22 п.п.

## Где менять

- `preprocessor.py` — команда `slice`.
- `SKILL.md` — раздел «Фаза 2»: перед запуском writer'ов прогнать `slice` для каждого сегмента, подавать `[CHUNK_сегмента]`.
- `subagent_phase2.md` — переименован вход `[CHUNK]` → `[CHUNK_сегмента]`.
