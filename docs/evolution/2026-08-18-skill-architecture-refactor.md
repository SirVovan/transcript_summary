# 2026-08-18 — Перекройка архитектуры скилла: SKILL.md → роутер + master.md + format_master.md, вынос ветки кадров, выпил «Траектории»

Крупнейшее изменение файловой архитектуры со времён перехода 2026-05-18. Событие охватывает **три сессии одного дня**: аудит под Opus (5 точечных упрощений, коммит `662bd43`), архитектурный аудит (отчёт, правок ноль) и реализацию — пять волн в отдельной ветке `feat/konspekt-arch-refactor` (от `feat/konspekt-widget-frames`; прежнее состояние осталось доступным по требованию владельца).

## Что изменилось

### 0. Точечные упрощения под Opus (`662bd43`, предыдущая сессия)

Скилл писался под более слабые модели; часть инструкций оказалась компенсирующими костылями. Внесены 5 согласованных правок (тикеты — `docs/superpowers/plans/2026-08-18-konspekt-opus-simplification-tickets.md`):

1. убрана строка-эхо про цепочку (И)→(М)→(Д);
2. разведены формулировки двух блоков самопроверки (дублировали друг друга);
3. сжато «железное правило стоимости» ветки кадров (смысл инварианта сохранён, объём сокращён);
4. почищены «Антипаттерны» Логической реконструкции;
5. убран ритуал «прочитай вслух».

**Отклонено при ручной перепроверке** (агенты предлагали срезать, оригинал показал обратное): блок «Анти-саботаж», микро-шаг «карта выделений», списки `profile_conference.md`, запрет вывода `_с_кадрами.md` в чат — это не разжёвывание, а защиты от реальных инцидентов.

### 1. Гигиена (`1bc4360`)

Удалён `_archive_2026-05-18/` вместе с вложенным `_archive_2026-05-04/` — 32 файла, 457 КБ **внутри тела скилла**: grep по скиллу вытаскивал архивные формулировки как действующие. История осталась в git. Список файлов в `SKILL.md` пересобран по факту (было 8 строк на 22 файла).

### 3. Возврат выбора режима и единый список меток (`8a5714f`)

**Выбор режима вернулся в ШАГ 0** — он был условием двух чекпойнтов, но сам вопрос исчез при переходе на архитектуру 2026-05-18, определение осталось только в удалённом теперь архиве. Владелец выбрал **полноценные два режима**:

| Чекпойнт | автоматический | с проверкой |
|---|---|---|
| ШАГ 1.2 — выбор заголовка | ждём выбор | ждём выбор |
| ШАГ 1.4 — карта сегментов | пропускается | ждём «ок» |
| ШАГ 4 — сохранение | сохраняем сразу | показать → «ок» → сохранить |

Это **отменяет прежнее правило** «карта ждёт «ок» даже в автоматическом режиме» (память обновлена в ту же сессию).

Три параллельных списка меток блоков сведены к одному в `format_master.md`; устранено расхождение «`layer2_widget.md` знает метку `Шаг N. Финальная формулировка`, парсер — нет».

## Почему так

**Причина перекройки — не эстетика, а бюджет и тихая деградация.** Архитектурный аудит (10 параметров, `docs/superpowers/plans/2026-08-18-konspekt-architecture-audit.md`) дал пять «Рисков», три из которых — один механизм: неизвестная метка → оранжевый, неизвестный тип сегмента → синий, отсутствующий `route` → не рендерится, и всё это под зелёным `✅ JS syntax OK`. Расширение `SEGMENT_TYPE_RULES` и единый список меток бьют по фолбэкам, а не по симптомам.

**Почему `format_master.md` отдельным файлом, а не разделом `master.md`.** Формат нужен обоим потребителям — и мастеру, и Слою 2. Пока он жил внутри `SKILL.md`, Слой 2 держал параллельное описание тех же правил; два описания расходились (метка `Шаг N. Финальная формулировка` — как раз такой случай).

**Почему сначала перекройка, потом текст.** 14 пунктов backlog из §2 отчёта под Opus правят методологию, которая переезжала в `master.md`. Правь их раньше — пришлось бы вручную переносить между файлами.

**Почему `route` не чинили.** Владелец уточнил факт, которого не было в файлах: Слой 3 выполняется всегда автоматически следом за Слоем 2, поэтому «парсится, но не рендерится» — норма, а не баг.

**Что осознанно не тронуто:** тройной повтор правила стоимости кадров (оправданный инвариант с историей инцидента), наблюдаемость ветки кадров, режим `preview` (исключён из обоих аудитов прямым указанием владельца).

## Где менять

- **Роутинг, команды, дисциплина** — `SKILL.md` (~9,8 КБ, читается всегда).
- **Методология мастера, ШАГ 0–4, выбор режима и чекпойнты** — `master.md`.
- **Контракт мастер-MD (шаблон сегмента, шапка, разделители, список меток блоков)** — `format_master.md`. Единственный источник; в `layer2_widget.md` его дублировать нельзя, только ссылаться.
- **Сборка виджета** — `layer2_widget.md`; **ветка кадров** — `layer2_frames.md` (opt-in, читать только при запросе кадров).
- **Цвета и типы сегментов** — `SEGMENT_TYPE_RULES` в `md_parser.py`. При добавлении нового типа в любой `profile_*.md` — дописать сюда, иначе тихий фолбэк в `concept`.
- **Разрезание секций мастер-MD** — `_split_sections` в `md_parser.py` (fence-aware, тесты в `tests/test_md_parser.py`).
