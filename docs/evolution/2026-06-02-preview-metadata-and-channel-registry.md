# 2026-06-02 — Метаданные автора/канала/даты в `preview` + детекция перезаливов по плейлистам

## Что изменилось

Шапка обзора `/konspekt preview` (Спикер · Канал · Дата выхода) больше не заполняется догадками — данные тянутся из источника. Ключевая сложность: часть видео — **чужие, залитые владельцем на свой канал-ферму** ради бесплатного авто-транскрипта, и для них метаданные YouTube фейковые (канал/автор/дата = ферма владельца, а не оригинал).

**Развилка против исходного ТЗ.** ТЗ предполагало отдельный «канал-помойку» и матчинг строго по `channel_id`. На деле у владельца перезаливы лежат в **двух выделенных плейлистах внутри его обычного канала** (`UCxFSGyMfQL5PBJIAy_vs4Lg`, «Владимир Купчинский»), где есть и собственный контент. Матчинг по каналу целиком пометил бы как «перезалив» и его авторские видео. По решению владельца (выбор в диалоге) матчинг — **по членству видео в dump-плейлистах**, с гейтом по каналу-ферме.

**Четыре части:**

1. **[youtube_to_srt.py](../../.claude/skills/konspekt/youtube_to_srt.py) — извлечение метаданных + детекция перезалива.**
   - `_get_video_title` заменён на `_get_video_metadata(url, cookies_browser) -> dict`: один вызов yt-dlp тянет `title, channel, channel_id, uploader, upload_date` через `--print` с шаблоном `%(field)s|||…` (разделитель `|||`). yt-dlp печатает `NA` для пустых полей → приводятся к `''`. `_format_upload_date`: `YYYYMMDD` → `YYYY-MM-DD`.
   - `_load_repost_config()` парсит `preview_repost_sources.md` рядом со скриптом — берёт только значения после `channel_id:` (строго `UC`+22) и `playlist_id:` (`PL`+), чтобы заглушки инструкций не попадали в реестр.
   - `_detect_repost(url, meta, cookies_browser) -> 'true' | 'unknown' | ''`: если `channel_id` видео НЕ в каналах-фермах → `''` (чужой канал перезаливом быть не может, без сети). Если ферма → достаёт video id из URL, тянет dump-плейлисты `--flat-playlist` и проверяет членство. Член → `'true'`. Сбой сети при проверке → `'unknown'`.
   - В `download_subtitles` шапка SRC: `# source:` всегда; `# channel:`/`# channel_id:`/`# uploader:`/`# upload_date:` — только для непустых полей; `# repost: true|unknown` — только если детекция сработала. `parse_srt` весь `#`-блок пропускает (нет таймстампа) — повторная переразбивка не ломается (проверено: 66 сегментов, шапка не в тексте).

   - Раздел «Каналы-фермы» (`channel_id:`) + раздел «Dump-плейлисты» (`playlist_id:`) + инструкция, как добавить. Заполнен реальными ID владельца: канал `UCxFSGyMfQL5PBJIAy_vs4Lg` и два плейлиста `PLMOwD8l9FRPFjw4iLH-KriqyprpF1bqP2`, `PLMOwD8l9FRPHFLw1NGcEPpDp-NebfmwR3`. Матчинг — по стабильным id, не по именам.

   - **ШАГ 1.3** перенаправлен на 2.2.

   - **ШАГ 2.6 (новый)** — профили `preview_profiles/`: ключ по `channel_id`/каналу (Ветка A) или имени автора (Ветка B); подтягивать молча, создавать только с согласия.
   - **ШАГ 3** — имя файла обзора получает **префикс канала**: `<Канал>_<название>_обзор.md` (в рабочей папке — `OUT_<Канал>_…`). Префикс только в имени файла, **не в H1**.

## Почему так

**Почему по членству в плейлистах, а не по каналу.** Ферма = обычный канал владельца с его собственным контентом вперемешку. Различитель «чужое vs своё» — это конкретные dump-плейлисты, куда складываются заливы. Матчинг по каналу целиком распознал бы авторские видео владельца как перезаливы.

**Почему гейт по каналу-ферме перед проверкой плейлистов.** Перезалив физически всегда на канале владельца, поэтому видео с чужим `channel_id` перезаливом быть не может — для него детекция возвращает `''` без сетевых запросов. Плейлисты тянутся только когда `channel_id` = ферма (редкий случай среди обзоров чужих оригиналов).

**Почему детекция в скрипте, а не в preview.md.** SRC становится самоописываемым: метка `# repost:` — готовый вердикт, ветвление в preview.md детерминированное, без рассуждений модели над выводом yt-dlp посреди обзора. Членство проверяется «вживую» при скачивании (без устаревающего кеша); SRC — снапшот, повторное скачивание перепроверит.

**Почему `unknown` отдельным значением.** Если `channel_id` = ферма, но плейлисты не дотянулись (сеть), ни «доверять метаданным» (риск фейка), ни «считать перезаливом» (риск оболгать свой контент) не безопасно по умолчанию. Честный путь — спросить владельца одним вопросом.

**Почему дату заливки перезалива прячем.** `upload_date` фермы = когда залили чужое, а не когда вышел оригинал. Показывать — врать зрителю обзора.

**Почему один вызов yt-dlp за всеми полями.** yt-dlp медленный на старте; один `--print` с разделителем `|||` тянет title + метаданные за проход.

**Почему запрет на выдумывание прописан явно.** Распознавание курса искажает имена/термины («Clills» вместо «Claude Skills»). Модель склонна «исправлять» их догадкой по фоновым знаниям и достраивать похожие названия каналов/проектов — это вносит ложь. Правило: чего нет в метках/транскрипте/ответе владельца — того нет.

**Почему префикс канала только в имени файла.** Владельцу нужно ориентироваться в списке `transcripts/`. H1 — смысловой заголовок видео, префикс канала там был бы шумом.

## Что осталось висеть

- **Перезаливы вне dump-плейлистов** (если владелец зальёт чужое мимо этих плейлистов) не распознаются — считаются авторскими. Лечится добавлением плейлиста в реестр.
- **Старые SRC, скачанные до этой версии**, не имеют ни метаданных, ни `# repost:` → идут как Ветка C (без ложного доверия).
- **Профили создаются на спросе** — папка стартует только с `README.md`.
- **Не-YouTube источники** по-прежнему вне охвата.
