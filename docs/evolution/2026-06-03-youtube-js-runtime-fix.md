# 2026-06-03 — Починка скачивания субтитров: JS-движок для yt-dlp

## Что изменилось

`youtube_to_srt.py` перестал скачивать субтитры для части видео — возвращал код 2 «нет субтитров», хотя у видео реально были авто-субтитры (`ru-orig`, `ru`). Причина — YouTube задепрекейтил извлечение без JS-runtime: для ряда видео URL дорожек субтитров отдаётся только после решения JS-challenge, а в окружении нет `deno` (единственный движок, включённый в yt-dlp по умолчанию).

**Правка одна, в [youtube_to_srt.py](../../.claude/skills/konspekt/youtube_to_srt.py):** в команду `_try_yt_dlp_subs` добавлены флаги `--js-runtimes node` (в окружении стоит node v22). Теперь yt-dlp решает JS-challenge через node и доходит до записи субтитров. CLI, коды выхода, остальной пайплайн не тронуты.

## Почему так

**Почему именно node.** В системе доступны node v22 и bun; `deno`/`qjs` нет. yt-dlp по умолчанию пробует только deno, поэтому challenge не решался. node — самый предсказуемый выбор из наличного.

**Почему правка только в запросе субтитров.** `_get_video_metadata` и `_fetch_playlist_video_ids` на проблемных видео отрабатывали без JS-движка — падал именно subtitle-запрос. Минимальная правка ровно там, где ломалось; остальные вызовы не трогал.

**Что это НЕ чинит.** Сам факт «есть субтитры или нет» по-прежнему определяется YouTube. Если у видео нет ни ручных, ни авто-субтитров — код 2 остаётся корректным.

## Где менять (применённая правка)

- `.claude/skills/konspekt/youtube_to_srt.py` — флаги `--js-runtimes node` в `_try_yt_dlp_subs`.

## Что осталось висеть

- **Жёсткая привязка к `node`.** Если на машине без node — флаг даст ошибку движка. Скрипт уже окружение-специфичен (Windows, служебный Edge-профиль), поэтому условную проверку наличия не добавлял; при переносе на другую машину учитывать.
- **Лимит длины пути Windows (260) — операционный нюанс, не правка скрипта.** При сохранении в глубокие кириллические папки полный путь `SRC_transcript_<длинный_slug>.srt` может превысить 260 символов, и запись падает с `No such file or directory` (в системе `LongPathsEnabled=0`). `cd` в папку + относительное имя НЕ помогает: Windows проверяет лимит по полному разрешённому пути. Лечится только укорачиванием имени файла (в кейсе 2026-06-03 уроки У16/У17 сохранены как `SRC_У16.srt` вместо полного slug). Скрипт генерирует длинные имена из заголовка — для глубоких папок это потенциальная мина; пока не автоматизировано.
