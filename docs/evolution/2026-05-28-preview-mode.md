# 2026-05-28 — Режим `/konspekt preview`: предварительная оценка видео

## Что изменилось

У скилла появился третий режим — `preview`. Команда:

```
/konspekt preview <путь к транскрипту или YouTube-URL>
```

Возвращает связный нарративный обзор ~800–950 слов (7 разделов, читается за ~5 минут) и рекомендацию: смотреть полностью / выборочно / пропустить + нужен ли полный мастер-MD. Один проход агента, без субагентов, без серийного контекста, без `profile_*.md`, без сопроводилок.

**Архитектура — режим внутри скилла, не отдельный скилл.**

- `SKILL.md` дополнен одной строкой в «Командах пользователя» и коротким диспетчерским блоком в конце (по аналогии с блоком «Виджет (Слой 2 + Слой 3)»).
- Самодостаточная методология — в новом `preview.md` (~230 строк) рядом с `SKILL.md`. Файл открывается явным «забудь правила мастер-MD из SKILL.md, применяй только то, что здесь» — это намеренная изоляция: правила сегментации, шаблона сегмента, голоса ToV, трёх уровней (И)/(М)/(Д) и самопроверки к обзору не применяются, это другой жанр.
- Связь с режимом `master` односторонняя через **рекомендацию** в финальном разделе обзора. Автоперехода нет — пользователь сам вызывает `/konspekt <путь>`.

**Шаблон обзора (7 разделов в строгом порядке):**

1. Шапка с метаданными (`Длительность · Спикер · Формат`).
2. `## Что это` — физика видео, проблемы записи, «стартовый шум» если есть.
3. `## О чём по сути` — сквозная тема, методология (списком 3–5 пунктов если есть).
4. `## Как раскрыто` — глубина, плотность, конкретика; «жемчужины» вне ядра.
5. `## На вынос` — 4–6 артефактов, которые можно применить.
6. `## Кому зайдёт` — целевая аудитория и кому будет мало.
7. `## Где смотреть` — единственная таблица в обзоре, фиксированные колонки `Минуты | Что | Решение`, словарь решений: `смотреть / по интересу / проматывать / пропускать`.
8. `## Рекомендация` — блокquote с двумя пунктами: смотреть как / глубина обработки.

Длительность для `.srt`/`.vtt` берётся из **последнего таймстампа в файле**, не из упоминаний времени в речи. Для `.txt`/`.md` без таймингов раздел «Где смотреть» становится словесным абзацем.

**Сохранение симметрично с мастер-MD:**

- Рабочая папка урока (`F:/.../М3-Д4.../SRC_*.srt`) → `OUT_<название>_обзор.md` рядом.
- `transcripts/` проекта → `<название>_обзор.md` без префикса `OUT_`.
- YouTube-вход всегда идёт через `transcripts/`.

**Утилита YouTube — `youtube_to_srt.py` в корне скилла.** `parse_srt`, `format_srt`, `rebucket` (склейка коротких сегментов yt-dlp в блоки по 30 секунд), `download_subtitles`, `main()`. Покрытие — 10 юнит-тестов (`tests/test_youtube_to_srt.py`). Скачивание через `yt-dlp` с приоритетным списком языков `(ru-orig, ru, en-orig, en)`. Имя итогового файла — `SRC_transcript_<slug>.srt` (с автодобавлением суффикса `_v2`, `_v3` при коллизии — никогда не перезаписывает молча).

**Cookie-проблема YouTube решена через служебный профиль браузера.** YouTube для большинства видео требует cookies авторизованного пользователя — анонимный yt-dlp получает «Sign in to confirm you're not a bot». Скрипт использует отдельный профиль в `%LOCALAPPDATA%/konspekt-youtube/<browser>-profile` (изолирован от основного браузера пользователя, не блокирует его cookies-базу) и передаёт `--cookies-from-browser <browser>:<service_path>` во все вызовы yt-dlp. По умолчанию — Edge; флаг `--cookies-browser chrome|firefox` для альтернатив. При пустом профиле — `exit 3` с готовой командой запуска служебного браузера для входа пользователя.

**Коды выхода скрипта:**
- `0` — успех, путь на stdout.
- `1` — неверные аргументы.
- `2` — у видео нет ни ручных, ни авто-субтитров.
- `3` — нужны cookies (служебный профиль пуст или YouTube требует подтверждение «не бот»); на stderr — инструкция.

**Реализация Python-кода — через `codex exec`** как одноразового сабагента (`parse_srt`+`format_srt`, потом `rebucket`, потом `download_subtitles`+CLI). Реальная экономия для скилла была скромная (3 задачи), но обкатали паттерн делегирования rewrite-задач Codex'у с тестами как контрактом. Заметка с замерами и рецептом — в vault, `knowledge/codex-as-subagent.md`.

## Почему так

**Зачем `preview` отдельным режимом, а не функцией мастер-MD.** Между «глянул видео — стоит ли вообще смотреть» и «прогнал через полноценный мастер-MD» была дырка. `/digest` смотрит источник через призму wiki (стоит ли пополнить базу), а тут нужно было оценить через призму обучения (стоит ли мне смотреть и делать конспект). Эта оценка должна быть дешёвой — пять минут чтения, один проход, без чтения сопроводилок и серийного контекста. Засунуть это в основной пайплайн `/konspekt` нельзя — там тяжёлая логика, которая всю эту экономию убьёт.

**Почему правила мастер-MD изолированы явно.** Когда `preview` живёт в той же папке скилла, агент при чтении `SKILL.md` рискует подхватить правила сегментации, шаблон сегмента и т.д. — это другой жанр, ему они не нужны. Поэтому в `preview.md` первая же секция — «забудь всё, что про сегментацию, шаблон сегмента, голос ToV, три уровня (И)/(М)/(Д), самопроверку, профили, серийный контекст». Дополнительно в `SKILL.md` есть диспетчерский блок: «увидел `preview` — читай `preview.md` и игнорируй всё остальное здесь». Двойная страховка от протечки.

**Почему YouTube-обвязка — общая утилита.** `youtube_to_srt.py` положен в корень скилла, а не внутрь `preview`. Логика скачивания и переразбивки пригодится и для будущих сценариев в режиме `master` (если когда-нибудь автоматизируем YouTube как источник). Без преждевременного обобщения — но без необходимости копировать код.

**Почему 30-секундные блоки.** yt-dlp выдаёт авто-субтитры мелкими сегментами по 2–7 секунд — для написания обзора это шум. 30 секунд — компромисс: достаточно крупно, чтобы читалось как абзацы, достаточно мелко, чтобы таймстампы оставались полезной навигацией.

**Почему не Playwright для авторизации YouTube.** yt-dlp нативно умеет `--cookies-from-browser edge|chrome|firefox|...` и лезет напрямую в SQLite cookies-базу. Playwright хранит cookies в своём storage state JSON — пришлось бы писать конвертер в Netscape cookies.txt, плюс зависимость на ~300 МБ chromium. Архитектурный мисфит без выигрыша. Логика служебного профиля портирована из проекта `D:\Скрипты\youtube_to_txt` (там она уже отлажена под Windows-специфику).

**Почему `-f sb0` (storyboard) во всех вызовах yt-dlp.** Свежий баг: на видео без стандартных видеопотоков (некоторые стримы, replays) yt-dlp даже с `--skip-download` пытается подобрать видеоформат и падает с `Requested format is not available`. Storyboard — самый легковесный формат, гарантированно доступен. Это применимо и к `--print title`, и к `--write-subs`/`--write-auto-subs`.

**Почему `--sub-langs orig` не подошёл.** План изначально предписывал `orig` как маркер «оригинального языка». yt-dlp понимает только языковые лейблы (`ru-orig`, `ru`, `en-orig`, `en` и т.д.). Заменили на приоритетный список с явным выбором первого скачанного по приоритету (не по alphabetic glob — иначе для русского видео с английскими auto-subs glob возьмёт `en` первым).

**Почему вариант B (режим), а не вариант A (плагин Claude Code).** Плагин требует больше структуры (`plugins/konspekt/skills/master/` + `plugins/konspekt/skills/preview/`), это шаг к реальной модульности — но избыточный сейчас. Режим внутри одного скилла — это просто один файл `preview.md` рядом с `SKILL.md`. Если завтра захочется плагин — миграция тривиальна, не тупик.

## Где менять (применённые правки)

- Создан `.claude/skills/konspekt/preview.md` (~230 строк) — самодостаточная методология режима.
- Создан `.claude/skills/konspekt/youtube_to_srt.py` — `parse_srt`, `format_srt`, `rebucket`, `_get_video_title`, `download_subtitles`, `_service_profile_root`, `_cookies_browser_spec`, `_find_browser_executable`, `_open_service_profile_hint`, `_pick_best_tmp_srt`, `_cleanup_tmp_srts`, `main()`.
- Создан `.claude/skills/konspekt/tests/test_youtube_to_srt.py` — 10 тестов (`parse_srt` x5, `rebucket` x5).
- `.claude/skills/konspekt/SKILL.md` — две правки: строка `/konspekt preview <путь или YouTube-URL>` в «Командах пользователя» + диспетчерский блок «## Режим `preview`» в конце.
- `CLAUDE.md` (корень проекта) — три режима скилла перечислены явно: master / виджет / preview.
- Параллельно (не связано с preview, но всплыло в той же сессии): SKILL.md ШАГ 4 — формализована логика сохранения мастер-MD в рабочую папку урока с префиксом `OUT_` (раньше был только `transcripts/[название]_мастер.md`).

## Что осталось висеть

- **Тесты на `download_subtitles`, `_pick_best_tmp_srt`, `main()`, обработку cookie-ошибок.** Сейчас покрыт только парсинг/переразбивка. CLI и обвязка проверены только end-to-end вручную — формальной защиты от регрессии в этих функциях нет.
- **Авто-обнаружение языка оригинала.** Сейчас `SUB_LANGS_PRIORITY` фиксирован как `(ru-orig, ru, en-orig, en)`. Для видео на других языках придётся либо расширять константу, либо принимать `--sub-langs` параметром CLI. Пока не делаем — текущий приоритет покрывает 99% случаев пользователя.
- **`-f sb0` как сайд-эффект.** Storyboard скачивается на диск как мусорный файл вместе с субтитрами (yt-dlp всегда дотягивает выбранный формат до конца). Сейчас не зачищается. Если будет мозолить — добавить в `_cleanup_tmp_srts`.
- **Возможный плагин Claude Code в будущем.** Если режимов станет больше (preview, master, widget, ещё что-то) или захочется устанавливать `/konspekt` в другие проекты — миграция в плагин по схеме `plugins/konspekt/skills/<режим>/` + `plugins/konspekt/shared/` для общих утилит.
