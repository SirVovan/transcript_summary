# 2026-06-04 — `preview`: одна рабочая папка на канал вместо папки на видео

## Что изменилось

Рабочая папка обзоров `/konspekt preview` в воркспейсе K_T_P перестала быть «папкой на видео» (`previews/<slug-видео>/`) и стала **папкой на канал** (`previews/<канал-slug>/`). Все обзоры одного автора лежат вместе.

**Три части:**

1. **[preview.md](../../.claude/skills/konspekt/preview.md) ШАГ 0.2 — скачивание YouTube.**
   - Раньше: `youtube_to_srt.py <URL> previews/<slug>/`, папка на видео, slug известен заранее.
   - Теперь: качаем во **временную** `previews/_tmp_<video-id>/` (имя канала ещё неизвестно до скачивания), затем по метке `# channel:` (ШАГ 0.3) переносим SRC в `previews/<канал-slug>/` и удаляем временную папку. Для известного канала slug берётся из его профиля в `preview_profiles/`.

2. **[preview.md](../../.claude/skills/konspekt/preview.md) ШАГ 3 — сохранение.**
   - Формулировка «транскрипт скачивается в `previews/<slug>/`, обзор идёт туда же» заменена на «после скачивания SRC уже перенесён в папку канала `previews/<канал-slug>/`, обзор сохраняется рядом с другими обзорами этого канала».

3. **[preview_profiles/README.md](../../.claude/skills/konspekt/preview_profiles/README.md)** — зафиксировано, что `<slug>` имени файла профиля = имя рабочей папки канала (`previews/<slug>/`), одна папка на канал.

**Сопутствующее применение (не часть скилла):** заведён первый профиль канала [iishenka.md](../../.claude/skills/konspekt/preview_profiles/iishenka.md) (`channel_id UCq_L4pHHIuWBW6OSKKxBbgw`, «ИИшенка | AI Automation») с заметками по ASR-искажениям этого канала; в воркспейсе K_T_P два его видео объединены из `dicnoabq/` и `lMAp8qL8vfY/` в `previews/iishenka/`.

## Почему так

**Почему по каналу, а не по видео.** Папка-на-видео плодит по каталогу на каждый обзор, и обзоры одного автора разбросаны. Группировка по каналу держит их вместе — удобнее ориентироваться и совпадает с тем, как уже устроены профили (`preview_profiles/` — один файл на канал). Решение владельца после того, как у канала ИИшенка обнаружились два обзора в разных папках.

**Почему через временную папку, а не сразу в папку канала.** Имя канала появляется только из метки `# channel:`, которую пишет `youtube_to_srt.py` уже при скачивании. До скачивания known только video-id из URL, поэтому целевую папку канала заранее не построить. Двухходовка (скачать в `_tmp_<video-id>/` → определить канал → перенести) разрывает эту зависимость без изменения скрипта.

**Почему slug из профиля для известных каналов.** Транслит имени канала на лету может слегка отличаться от раза к разу. У канала с профилем slug фиксирован (= имя файла профиля), поэтому папка стабильна. Для нового канала без профиля slug определяется транслитом — расхождение возможно только до заведения профиля.

## Где менять (применённые правки)

- `.claude/skills/konspekt/preview.md` — ШАГ 0.2 (временная папка + перенос по каналу), ШАГ 3 «Куда».
- `.claude/skills/konspekt/preview_profiles/README.md` — slug профиля = папка канала.
- `.claude/skills/konspekt/preview_profiles/iishenka.md` — новый профиль (применение).

## Что осталось висеть

- **Скрипт `youtube_to_srt.py` не трогали** — перенос делает основной агент по метке `# channel:`. Альтернатива (скрипт сам кладёт в папку канала) не реализована: потребовала бы дать скрипту доступ к `preview_profiles/` для разрешения slug.
- **Новый канал без профиля** получает slug транслитом на лету — до заведения профиля возможна папка с чуть иным написанием.
- **Старые обзоры в папках-по-видео** (кроме перенесённого ИИшенка) не мигрированы — переносятся по мере следующего обзора того же канала или вручную.
