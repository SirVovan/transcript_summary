## Ключевые решения (и почему)
- **Накопление корпуса с этого момента + бэкфилл из локальных транскриптов** (не выгрузка вручную). Транскрипты лежат в `~/.claude/projects/<folder>/*.jsonl` — их можно грепать.
- **Детект правок — по репликам пользователя, а не по ключевым словам.** Маркеры дают плохой recall (правку формулируешь как угодно). Реплики короткие, в них суть; читаю их первыми, затем точечно тяну контекст. Артефактный дифф заголовков — вторичен и слаб: финальный мастер пишется в ФАЙЛ через инструмент, в текст чата не попадает.
- **Чек-лист ветвится по типу урока** — требования противоречивы (лекция→ступени, Q&A→вопросы и не укрупнять, рассказ→по граням), плоский список не сработал бы. Это вывод из корпуса, не из головы (evidence first).
- **Не полный superpowers-пайплайн, а точечные правки** — это проза одного скилла, не многофайловый код. Эвалы через skill-creator отложены (Фаза 4), делать только если глазами мало.
- **Главный вывод корпуса:** скилл оптимизировал под удобство пишущего (механика: счёт сегментов, минуты), а не понимание читателя. Все споры — симптомы этого.

## Грабли / чего избегать
- **Механические якоря в SKILL.md не нейтральны** — раньше «5–10 сегментов», «масштаб как в прошлых частях» активно провоцировали отвергаемое поведение. Не возвращать счёт в драйверы.
- **Сбой активации повторялся** («записали в профиль — почему не подтянул?», 24–25 мая). Преемственность лечится подтяжкой `tov_<серия>`+прошлых мастеров в момент заголовков, а не ещё одним текстом правила.
- **Codex/субагенты** хороши только на механике (экстракция корпуса — отработали). Прозу ядра скилла НЕ делегировать — теряется контекст.
- **Был сбой UI:** после `git diff` мой ход оборвался без текста — выглядело как «завис». Если кажется, что подвис — просто переспроси, не теряй время.
