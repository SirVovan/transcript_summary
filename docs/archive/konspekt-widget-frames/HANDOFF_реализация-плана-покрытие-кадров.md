Дата: 2026-07-10 · Проект: konspekt-project (ветка `feat/konspekt-widget-frames`)

## Цель

Реализовать по TDD исправленный план [docs/superpowers/plans/2026-07-07-konspekt-widget-frames-coverage.md](docs/superpowers/plans/2026-07-07-konspekt-widget-frames-coverage.md) — доработку opt-in ветки «виджет с кадрами» скилла `/konspekt`. Суть доработки: заменить шумную позиционную детекцию/вставку кадров на детерминированную привязку кадр→сегмент по таймкоду, pHash-дедуп катов камеры, посегментные квоты и двухфазный отбор с гарантией ≥1 кадра на сегмент. **Код по плану ещё не писался** — план прошёл ревизию и готов к исполнению.

## Сделано (в этой сессии)

- Прогнано критическое ревью плана (вместо недоступного Codex, по промпту [PROMPT_codex-ревью-план-покрытие-кадров.md](PROMPT_codex-ревью-план-покрытие-кадров.md)). Вердикт: было `REQUEST_CHANGES`, после правок — `APPROVE`.
- Закрыты **две блокирующие находки** + 4 некритичных, все правки внесены в файл плана:
  - **К1 (тест pHash):** `test_phash_dedup_cycle_ababa_window3` → `..._abca_...`. Причина: `average_hash` бинаризует по среднему яркости → у **сплошной заливки все 64 бита = 1 одинаково для любого цвета**, hamming=0 попарно, тест не стал бы зелёным. Заменил solid-фикстуры на паттерны (лево/право, верх/низ, инверсия), A==D. Проверено руками: hamming попарно 32/64/32, D→A = 0, окно N=3 реально проверяется.
  - **К2 (петля веса ≤8 МБ):** `trim_to_weight` была функцией **без вызова** — вес итогового HTML нигде не измерялся. Добавлена **Task 4.4**: замкнутая петля build→вес→обрезка→ребилд.
  - Н1: убран no-op `--dry-run` из подкоманды `extract`. Н2: задокументирован риск pHash сквозь границы бакетов + критерий E2E. Н3: уточнена терминология «единый нисходящий cap» vs спечное «пропорционально». Н4: зафиксирован инвариант `cap ≥ числа сегментов`.

## Ключевые решения (и почему)

- **Петля веса живёт в `widget_generator`, а не в `select`** — так `phase`/`confidence` к моменту сборки берутся из `shortlist.json` через новый флаг `--shortlist`, без проброса через парсер.
- **`cand_id` протаскивается через `data-cand="NN"` на `<figure>`** — удаление проигравших по весу картинок хирургическое (regex по HTML), без повторного парсинга MD.
- **overhead (CSS/JS/текст) считается приближённо** — «итог минус вес картинок»; для порога 8 МБ точности хватает (лимит с запасом).
- **«Сначала сильнее сжать, потом резать» — в MVP только фиксированное сжатие 1280/q82 + обрезка**; динамическое пере-сжатие отложено (YAGNI).
- Все 4 решения по К2 — мои допущения; пользователь их видел и не возражал, но при реализации можно скорректировать.

## Грабли / чего избегать

- **Не тестировать `average_hash` сплошными заливками** — они неотличимы (см. К1). Только структурные картинки (паттерны/градиенты).
- **pHash-окно скользит через границы сегментов** (raw отсортирован по таймкоду) — может изредка гасить первый кадр сегмента, похожий на хвост предыдущего. Принято как компромисс, проверяется глазами на E2E (Task 7.1 Step 4, критерий «б»).
- **Скилл под junction** `~/.claude/skills/konspekt` → этот репозиторий; правки делать здесь.
- **Push и PR не делать** — пользователь сам. Коммиты — частые локальные, по одному на задачу (сообщения даны в плане).
- Запуск питона скилла и тестов: `PYTHONUTF8=1 python ...`; тесты — `PYTHONUTF8=1 python -m pytest .claude/skills/konspekt/tests/ -q`. Windows/PowerShell основной, Bash доступен.
- Не выводить в чат содержимое PNG-кадров или полный `MASTER_..._с_кадрами.md` (существующий запрет в `layer2_widget.md`).
