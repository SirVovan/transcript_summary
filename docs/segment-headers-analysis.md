## Часть 1. Типовые проблемы (что правится из раза в раз)

### Заголовки
| # | Проблема | Цитата-эталон |
|---|---|---|
| P1 | Технические / «тупые» / назывные заголовки — описывают форму, не суть | «заголовки тупые, чисто технические» (Д10) |
| P2 | Антитеза «не А, а Б» в заголовке | «агент начинается с ТЗ, а не с кода» → переписан (У15) |
| P5 | Не ориентированы на читателя / на пользу | «не все ориентированы на читателя» (У15) |
| P6 | Жирным весь заголовок (надо только до двоеточия) | «не делай полностью жирными» (У15) |
| P7 | Ответ в заголовке вместо вопроса (для Q&A/разборов) | «не надо сразу ответ в заголовке, делай в виде вопросов» (Д10) |
| P8 | Слишком длинные / развёрнутые / непонятные | «очень длинные и непонятные» (ч2); «подсократи» (Велс ч2) |
| P9 | Нет преемственности / не отражают единый процесс (для лекций-методологий) | «утрачена преемственность, заголовки = отражение архитектурного процесса» (Велс ч2) |
| P10 | «Чёрный ящик»: длинный сегмент — одна абстрактная фраза, непонятно что внутри | «7 минут — и что там происходит? звучат абстрактно» (26.05) |
| P11 | Пестрят терминами, нечитабельны | «сделай человеческими, чтоб прочитал и понятно» (Велс ч2) |

### Границы сегментов
| # | Проблема | Цитата-эталон |
|---|---|---|
| B1 | Размельчение (слишком много мелких) | «26 сегментов много» (Д10) |

## Часть 2. Глубинные принципы (из принципиальных диалогов)

1. **Смысловой критерий — главный; механический (счёт, минуты, «как в прошлых частях») — вторичен.**
   Повторяется чаще всего: «не оценивай сегменты арифметически… смысловая оценка — главный критерий, размер может быть любой» (16.05); «опять привязываешься к количественному» (26.05). Размер сегмента — следствие смысла, не цель.

2. **Заголовок честно сообщает, что внутри (тест на чёрный ящик).**
   Если сегмент длинный, а заголовок — одна короткая абстрактная фраза, читатель не понимает, что там 7–20 минут. Заголовок должен давать «адекватное представление, что происходит».

3. **Две роли: пишешь — глазами спикера, проверяешь — глазами читателя.**
   При написании: «какую ценность этот сегмент даёт читателю?». При самопроверке: «понятна ли мне идея автора, причинно-следственные связи, складывается ли картина?». Самопроверка обязательно с позиции читателя.

4. **Преемственность как единый архитектурный процесс (для лекций-методологий).**
   Заголовки частей серии — звенья одного маршрута («Этап N — …»), «вайб» преемственности держится через `profile_lecture` + `tov_<серия>`. Пользователь дважды отметил: правило записано, но агент его **не подтягивает** — это та же корневая проблема активации.

5. **Гибкость по типу материала.**
   Есть сквозная нить/методология → лестница этапов. Нет нити (просто рассказ/идея) → другой подход. «Нельзя по жёсткой схеме — смотри, что за материал».

6. **Человеческий язык, ёмко но не куце.**
   Между двух огней: слишком абстрактно (P10) и слишком длинно/терминологично (P8, P11). Цель — узкая полоса: ёмкая конкретность простыми словами.

## Часть 3. Собственный анализ агента (мета-уровень)

**Корень один: скилл оптимизирует под удобство ПИШУЩЕГО (механические, легко-защитимые эвристики), а не под понимание ЧИТАТЕЛЯ.** Все повторяющиеся споры — симптомы этого:
- счёт сегментов вместо смысла (B1–B3 ↔ принцип 1);
- абстрактно-красивый заголовок вместо честно-информативного (P10 ↔ принцип 2);
- термины вместо простого языка (P11 ↔ принцип 6).

Отсюда выводы, которых нет в текущем скилле:

1. **Механические якоря в `SKILL.md` не нейтральны — они активно тянут агента к отвергаемому поведению.** Формулировки «5–10 сегментов на 60–90 мин», «15+ = размельчение», «серийный контекст как эталон масштаба» — это ровно то, что пользователь раз за разом перебивает «смысловым критерием». **Рекомендация:** понизить счёт до пост-проверки на вменяемость, а не драйвера; вести от смысла. Сейчас счёт стоит впереди смысла — это провоцирует регресс.

2. **Сбой активации подтверждён и повторяется.** «Мы записали в профиль — почему не подтянул?» звучит в 24.05 и 25.05. Преемственность заголовков лежит в `profile_lecture`, но не срабатывает — тот же корень, что и в основной задаче. Значит лечить надо не текстом правила, а **точкой применения**: чек-лист + форсирующая самопроверка в ШАГ 1.4.

3. **«Тест на чёрный ящик» — готовый конкретный гейт.** Для каждого заголовка: «если я прочитаю ТОЛЬКО его — пойму ли, что происходит в эти N минут?». Длинный сегмент + одна абстрактная фраза = чёрный ящик, переписать. Это операционализирует принцип 2 без абстракций.

4. **Самопроверка глазами читателя — это и есть форсирующий механизм, который пользователь просил ещё в мае.** Он был собран как role-based self-checks (spec 16.05), но на этапе заголовков по-прежнему не стреляет. Нужно прицельно повесить его на ШАГ 1.4 (до показа карты).

5. **Заголовки-вопросы для Q&A — отдельная ветка профиля.** В разборах/Q&A заголовок = вопрос участника, не ответ; сегментацию не укрупнять. Это не общий дефект, а профиль-специфика (как лестница этапов для лекций).

## Часть 4. Что из этого следует для ШАГ 1.4

Чек-лист заголовков должен **ветвиться по типу материала**, а не быть плоским:

- **Общее (все типы):**
  - смысл ведёт, счёт/минуты — только пост-проверка;
  - тест на чёрный ящик (заголовок честно говорит, что внутри);
  - простой человеческий язык, без термин-каши; ёмко, но не куце;
  - без антитез «не А, а Б»; жирная только часть до двоеточия;
  - обязательная самопроверка глазами читателя ДО показа карты.
- **Лекция-методология (есть нить):** заголовки = сквозные ступени «Этап N — …»; подтянуть преемственность из `tov_<серия>` и предыдущих `*_мастер.md`.
- **Q&A / разборы:** заголовок = вопрос участника, не ответ; Q&A-блоки и вставки — отдельными сегментами, не сливать.
- **Рассказ/идея (нет нити):** не натягивать лестницу; заголовки по граням главной мысли.
