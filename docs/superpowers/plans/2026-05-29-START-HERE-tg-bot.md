## Что мы вообще делаем

Запускаем разработку Telegram-бота, который делает обзоры YouTube-видео по скиллу `/konspekt preview`. План разбит на 6 фаз, ~30 задач. Реализует **новая сессия Claude Code**, которую ты запустишь и которой будешь давать команды между фазами.

**Сколько времени:** одна фаза — 1-3 часа активной работы Claude. Между фазами ты можешь делать паузы любой длины (день, неделя — без разницы).

**Что от тебя нужно:** запустить новую сессию, отправить 1 длинное сообщение в начале, потом 6 коротких команд между фазами. Всё.

## Шаг 3. Наблюдай Фазу 0 + 1

Что должно происходить:

1. Claude (Opus 4.8) загружает план, объявляет «использую subagent-driven-development».
2. Спавнит **Sonnet-subagent** на Task 0.1 (скелет проекта). Через 2-5 минут получает результат.
3. Сам ревьюит результат, может попросить subagent доработать.
4. Коммитит результат через `git commit`.
5. Переходит к Task 0.2 (разделение `preview.md`). На этой задаче спавнит **Opus-subagent** (помечена как Opus, потому что тонкая работа со смыслом).
6. После Task 0.2 — запускает **Codex** через bash для независимого ревью.
7. И так далее, по списку задач плана.

**Что делать тебе:** обычно ничего. Сиди, читай чат, смотри прогресс. Можешь отойти.

Между задачами Claude будет писать что-то вроде «Task 0.1 завершён, commit `abc1234`, перехожу к Task 0.2». Это нормально.

### Когда Claude может остановиться и спросить тебя

| Ситуация | Что делать |
|---|---|
| Тест в задаче 0.2 (поведенческая инвариантность preview.md) требует ручной проверки на сохранённой лекции | Claude скажет «прогони `/konspekt preview <путь>` и сравни с OUT_*_обзор.md». Сделай это в **отдельной сессии Claude** (просто открой ещё одно окно), ответь в основной «совпадает» или «расхождения такие-то». |
| Codex-ревью нашёл проблему | Claude предложит план фикса. Скажи «давай», если согласен. |
| Pytest падает в задаче, subagent не может починить с 2-х попыток | Claude эскалирует тебе. Прочитай ошибку, скажи «попробуй X» или «давай я сам гляну». |
| Конфликт в архитектурном решении | Claude задаст уточняющий вопрос. Ответь, как считаешь правильным. |

## Шаг 6. Фаза 6 — реальный запуск бота

Это последняя фаза, и тут от тебя нужно немного больше.

В Фазе 6 будет verification-чеклист — попытка реально запустить бота и попробовать через Telegram. Чтобы это сработало, до запуска (или прямо в процессе Фазы 6) нужно подготовить:

- [ ] **Создать нового Telegram-бота:**
  - Написать [@BotFather](https://t.me/BotFather), `/newbot`, придумать имя и username.
  - Сохранить токен — он пойдёт в `bot/.env` как `TELEGRAM_BOT_TOKEN`.
  - ⚠️ Это **отдельный** бот, не тот что в Telegram-плагине Claude Code.

- [ ] **Узнать свой Telegram user_id:**
  - Написать [@userinfobot](https://t.me/userinfobot), `/start`.
  - Скопировать `Id` → пойдёт в `bot/.env` как `OWNER_USER_ID`.

- [ ] **Сгенерировать `KEYS_ENCRYPTION_KEY`:**
  ```powershell
  python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
  ```
  Скопировать вывод в `bot/.env`. ⚠️ При потере все гостевые ключи нерасшифровываются.

- [ ] **Гостевой Google-аккаунт для Gemini:**
  - Завести **отдельный** Google-аккаунт (не личный — под бота).
  - На https://aistudio.google.com/apikey получить ключ.
  - Положить в `bot/.env` как `GUEST_GEMINI_API_KEY`.

- [ ] **US-прокси:**
  - Купить/настроить.
  - Формат `http://user:pass@host:port` положить в `HTTPS_PROXY` и `HTTP_PROXY` в `.env`.

- [ ] **YouTube-cookies:**
  - Один раз войти в YouTube через служебный профиль Edge (Claude покажет команду из `youtube_to_srt.py` при первом запуске).

Claude в Фазе 6 спросит про каждый пункт. Если что-то не готово — можно сказать «отложим», и он сделает всё кроме реального запуска.

## Если что-то пошло не так

### Claude не следует распределению по моделям, всё делает Opus

Скажи в чат:
```
Подожди. Проверь execution-distribution и используй model="sonnet" для
задач, помеченных как Sonnet. Сейчас ты неоправданно тратишь Opus-квоту.
```

### Тесты падают, subagent не чинит

Скажи:
```
Покажи мне ошибку pytest. Может быть, проблема не в коде, а в спеке.
```

Дальше — по ситуации. Если spec реально некорректен — отредактируем spec, перезапустим задачу.

### Codex-ревью ругается, я не понимаю на что

Скажи:
```
Объясни замечание Codex простыми словами. Это критично или можно игнорировать?
```

### Кончилась дневная квота Max

Закрой сессию. Завтра продолжи (см. «Если сделал паузу»).

### Я хочу поменять spec в середине процесса

Скажи:
```
Стоп. Хочу обсудить изменение в spec по такой-то задаче — [твой запрос].
```

Claude остановится, обсудит, поправит spec и план, продолжит после твоего ок.

### Бот не работает после Фазы 6 / verification провалился

Claude в Фазе 6 покажет, какой именно шаг verification провалился. По нему и будем чинить — каждый шаг ведёт к конкретному компоненту.
