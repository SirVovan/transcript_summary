# Спецификация: скилл `/konspekt-preview` — предварительная оценка видео

**Дата:** 2026-05-28
**Статус:** дизайн согласован, готов к плану реализации
**Происхождение:** [Summary_instruction.md](../../../Summary_instruction.md) — изначальный запрос пользователя; брейнсторм в этой сессии

---

## Контекст и проблема

Сейчас в проекте есть два рабочих скилла:

- **`/konspekt`** — полноценная переработка транскрипта в мастер-MD (тяжёлый процесс).
- **`/digest`** — оценка источника через призму **wiki** (стоит ли пополнить базу знаний).

Между ними — **дырка**. Когда видео попадает в руки, не очевидно, стоит ли его вообще смотреть с прицелом на конспект, какие участки самые ценные, и нужен ли полный мастер-MD или достаточно беглого ознакомления. Сейчас этот вопрос решается на ощупь: открыть, посмотреть кусочками, потом вернуться. Дорого по вниманию.

Нужно **«первое касание»** — дешёвый ознакомительный шаг, который за пять минут чтения даёт целостное представление о видео и подсказывает, как с ним поступить.

---

## Решение

Новый мини-скилл **`/konspekt-preview`**. Один проход агента: транскрипт → связный нарративный обзор ~800–950 слов. Без субагентов, без чанкования, без чтения сопроводительных материалов, серийного контекста и wiki. Только сам транскрипт.

Обзор закрывает три плоскости одновременно:

1. **Go / no-go** — стоит ли вообще смотреть.
2. **Стратегия просмотра** — какие участки приоритетны.
3. **Глубина обработки** — нужен ли полный мастер-MD или достаточно беглого знакомства.

---

## 1. Команда и вызов

**Имя:** `/konspekt-preview` (с дефисом — чтобы не путать с `/konspekt`).

**Использование:**

```text
/konspekt-preview <путь к транскрипту или YouTube-ссылка>
```

Если аргумент не указан — скилл спрашивает: «Какой файл оцениваем? Укажи путь или YouTube-ссылку».

---

## 2. Входы

### 2.1. Локальный транскрипт

Поддерживаемые форматы:

- `.srt` (с таймингами) — основной формат
- `.vtt` (с таймингами)
- `.txt` / `.md` (без таймингов — карта времени становится словесной)

### 2.2. YouTube-ссылка

Если аргумент — URL вида `https://www.youtube.com/watch?v=...` или `https://youtu.be/...`, скилл сначала скачивает транскрипт.

**Алгоритм скачивания:**

1. Запустить `yt-dlp` со скачиванием субтитров (без видео):
   - сначала пытаемся **ручные субтитры** на оригинальном языке видео;
   - если ручных нет — берём **авто-генерированные**;
   - если нет ни ручных, ни авто-генерированных — **отказываем** с инструкцией: «У этого видео нет субтитров. Транскрибируй отдельно (Whisper или сервис) и подавай `.srt` напрямую».
2. yt-dlp выдаёт SRT с **исходными короткими сегментами** (2–7 секунд каждый).
3. Python-скрипт `youtube_to_srt.py` склеивает сегменты в **блоки по 30 секунд**.
4. Результат сохраняется как `transcripts/SRC_transcript_<title>.srt`. Префикс `SRC_transcript_` помечает файл как исходник для последующих скиллов (`/konspekt-preview`, `/konspekt`). Если файл с таким именем уже есть — дописать суффикс `_v2`, `_v3` и т.д. (никогда не перезаписывать молча).
5. Дальше — стандартный поток оценки.

**Язык вывода:** обзор всегда пишется **по-русски**, независимо от языка транскрипта. Если оригинал на английском (или другом) — Claude переводит смысл естественно при написании обзора.

### 2.3. Размер транскрипта

Если транскрипт `>` 30 000 токенов (приблизительно `>` 2 часов лекции) — попросить пользователя разрезать на источнике, как в `/konspekt`. Каждый кусок оценивается отдельно.

---

## 3. План работы агента

Один проход, без вложенных шагов.

1. **Получить транскрипт.** Если на входе YouTube-ссылка — выполнить скачивание (раздел 2.2). Иначе — прочитать указанный файл.
2. **Прочитать транскрипт целиком.**
3. **Определить длительность.** Для `.srt`/`.vtt` — из **последнего таймстампа**, не из упоминаний времени в речи. Для `.txt`/`.md` без таймингов — оценка по объёму («примерно N минут»).
4. **Определить имя спикера.** Из транскрипта (если представляется) или из имени файла.
5. **Написать обзор** по форме раздела 4.
6. **Показать в чате.**
7. **Сохранить автоматически** (раздел 5). Отчитаться одной строкой.

**Что агент НЕ делает:**

- Не читает `profile_*.md`.
- Не читает предыдущие `*_мастер.md` серии.
- Не читает сопроводительные материалы (`.pptx`, презентации, скрины промптов).
- Не читает `tov_<серия>.md`.
- Не сравнивает с wiki.
- Не использует `TodoWrite`.
- Не запускает субагентов.

Это намеренная **дешевизна первого касания**.

---

## 4. Формат отчёта

### 4.1. Принципы

- **Связный нарративный рассказ**, не маркерные блоки.
- **~800–950 слов**, читается за ~5 минут.
- **Голос спокойного знающего коллеги** — без академического дистанцирования, без рекламной интонации, без панибратства. Близко к голосу мастер-MD `/konspekt`.
- **Простой язык** — без «риторической дуги», «фундамента, который держит», «глубинного зачем».
- **Жирное** — сжатые формулировки ключевых мыслей абзацев, по тем же правилам, что в `/konspekt`.
- **Без ASCII-схем, без Mermaid-диаграмм, без шапок-карточек в `code-fence`** — этот баланс проверен в пилотировании, утяжеляет восприятие.
- **Тон — описательный, не оценочный**: не «отличное видео», а «методология стройная, артефактов много».

### 4.2. Структура (7 разделов)

```markdown
# [Короткий заголовок видео]

*[Подзаголовок-курсивом — одна фраза про суть.]*

**Длительность:** [HH:MM] (полезного потока ~[HH:MM]) · **Спикер:** [имя] · **Формат:** [короткое описание]

---

## Что это

[1–2 абзаца. Физика видео: формат, темп, кто говорит, как устроен экран,
видимые проблемы (плохой звук, не открылась презентация, и т.п.).
Если есть «стартовый шум» — упомянуть с минутой, до которой можно мотать.]

> **Имей в виду:** [одно предложение про главное предупреждение для зрителя,
> если есть. Например: «первые ~10 минут — про связь, можно проматывать».
> Если нет — блок опускается.]

---

## О чём по сути

[2–4 абзаца. Сквозная тема, риторическая позиция автора, главная мысль одной
фразой. Если у автора есть отчётливая методология — она перечисляется
маркированным списком из 3–5 пунктов внутри этого раздела (список даёт
«остров» для глаза, не ломая поток).]

---

## Как раскрыто

[2–3 абзаца. Глубина, плотность, конкретика — словами, не баллами. Где ядро,
где Q&A, есть ли «жемчужины» в неожиданных местах. Дословные шаблоны
(промпты, фразы) — курсивом в кавычках, если они короткие; жирное на ключевых
формулировках. Список из 2–4 опор внутри раздела допустим.]

---

## На вынос

[1 строка-зацепка + маркированный список из 4–6 конкретных артефактов,
которые можно взять и применить. Каждый пункт — с жирным заголовком и
коротким пояснением: `- **Артефакт:** что это и где применить`.]

---

## Кому зайдёт

[1–2 абзаца простой прозой. Один абзац про целевую аудиторию,
один — про кому будет мало нового. Без таблиц.]

---

## Где смотреть

| Минуты | Что | Решение |
| --- | --- | --- |
| 00:00 – HH:MM | [описание участка] | смотреть / по интересу / проматывать |

[Таблица 3–5 строк. Если транскрипт без таймингов — раздел заменяется
на абзац словами («первая треть — то-то; ядро в середине; концовка — Q&A»).]

---

## Рекомендация

> **Смотреть [полностью / выборочно / пропустить].** [Конкретика по участкам.]
>
> **Глубина обработки:** [полный мастер-MD через `/konspekt` /
> краткое саммари / не нужно]. [Если нужны сопроводилки для `/konspekt` —
> явно сказать, что приложить.]
```

### 4.3. Раздел «Где смотреть»

Это **единственный табличный элемент** в обзоре. Решено отдельно — таблица в этом месте работает как компактная навигационная карта, не утяжеляет восприятие. Колонки — фиксированные: `Минуты | Что | Решение`. Значения колонки «Решение» — из ограниченного словаря: `смотреть`, `по интересу`, `проматывать`, `пропускать`.

### 4.4. Что НЕ должно быть в обзоре

- Метрики, баллы, проценты.
- ASCII-арт, Mermaid-диаграммы, Unicode-полоски.
- Шапки-карточки в `code-fence`.
- Длинные цитаты из транскрипта (> 1 строки).
- Имена участников чата (если речь о Q&A — описывать без имён).
- Личные впечатления агента («мне понравилось», «я считаю»).
- Оценочные эпитеты («отличное», «гениальное», «слабое»).

---

## 5. Сохранение

**Автоматически**, без вопроса.

**Куда:**

- Если транскрипт лежит в **рабочей папке урока** (например, `F:/.../М3-Д4.../SRC_*.srt`) — обзор сохраняется **рядом** как `OUT_<название>_обзор.md`. Симметрично с тем, как `/konspekt` кладёт `OUT_<название>_мастер.md`.
- Если транскрипт лежит в `transcripts/` проекта — обзор сохраняется туда же как `<название>_обзор.md`.
- Для YouTube-входа транскрипт изначально кладётся в `transcripts/`, поэтому обзор сохраняется туда же.

**Отчёт в чате после сохранения:**

```text
Обзор готов: [путь]/[название]_обзор.md
```

## 6. Стыковка с другими скиллами

### 6.1. С `/konspekt`

Связь односторонняя: `/konspekt-preview` в разделе «Рекомендация» **явно указывает**, нужен ли последующий `/konspekt`. Автоматический запуск не делается — пользователь вызывает `/konspekt` отдельной командой.

`/konspekt` остаётся **независимым**: не предполагает, что обзор уже сделан. Если обзор есть рядом — `/konspekt` его не читает (это разная аналитика, обзор не серийный контекст).

### 6.2. С `/digest`

Скиллы **дополняют друг друга**, не пересекаются:

- `/digest` — «стоит ли пополнить wiki этим материалом» (через призму базы знаний).
- `/konspekt-preview` — «стоит ли мне как ученику смотреть это видео и делать конспект» (через призму обучения).

Оба могут вызываться на одном источнике в любом порядке.

---

## 7. Граничные случаи

- **Транскрипт > 30 000 токенов** → попросить разрезать на источнике, как `/konspekt`.
- **Нет таймстампов** (`.txt`/`.md`) → раздел «Где смотреть» становится словесным абзацем; длительность оценивается по объёму.
- **Очень короткий транскрипт** (< 5 минут полезного потока) → обзор сжимается до 300–500 слов, разделы могут схлопываться (например, «Что это» и «О чём по сути» сливаются).
- **Несколько спикеров** → описать «двое ведут разговор», «панельная дискуссия из четырёх человек»; имена не персонифицировать, если не критично.
- **Транскрипт явно мусорный** (битый, не транскрипт, машинный перевод плохого качества) → коротко сообщить о проблеме и спросить пользователя, продолжать ли. Не пытаться писать обзор поверх мусора.
- **YouTube-видео без субтитров** → отказать с инструкцией (см. 2.2).
- **YouTube-видео > 2 часов** → скачать транскрипт, но затем попросить разрезать на куски.

## 8. Файлы скилла

- `.claude/skills/konspekt-preview/SKILL.md` — методология и формат (компактно, ~150–200 строк).
- `.claude/skills/konspekt-preview/youtube_to_srt.py` — скачивание и переразбивка YouTube-транскрипта.

Без хуков, без субагентов, без `widget_generator.py`-аналогов. Минимальный набор.

---

## 9. Что НЕ входит в скоуп

- **Серийный контекст.** Не читает предыдущие мастер-MD серии. Это первое касание, ему не нужен «эталон масштаба».
- **Сопроводительные материалы.** Не читает `.pptx`, презентации, скрины промптов. Это работа `/konspekt`.
- **Пакетная обработка.** Один транскрипт за вызов. Список ссылок — отдельным запросом по очереди.
- **Локальная транскрибация.** Whisper и аналоги не вызываются. Если у YouTube-видео нет субтитров — отказ с инструкцией.
- **Сравнение с wiki.** Это работа `/digest`.
- **Постобработка обзора.** Виджет, HTML-версия, экспорт в Notion — не входят. Только Markdown-файл.

---

## 10. Дисциплина

- **Не использовать `TodoWrite`** — пайплайн линейный, прогресс виден из текста.
- **Не запускать субагентов.**
- **Не предлагать улучшения транскрипта** (groom, очистку шумов распознавания) — это работа `/groom`, у обзора своя задача.
- **Никогда не вызывать `/konspekt` автоматически** — даже если рекомендация «делать полный мастер-MD». Решение запуска — за пользователем.
