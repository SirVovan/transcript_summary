# Дизайн: ключевые кадры видео в виджете `/konspekt`

**Дата:** 2026-07-02
**Статус:** одобрен к планированию (учтено ревью Codex)
**Скоуп:** только режим виджета (Слой 2). Режимы master-MD и preview как продукты не меняются.

## Задача

Научить ветку виджета находить в видео ключевые кадры (слайды, промпты на экране, инфографику), скринить их и вставлять в HTML-виджет:

- **текст** (промпт или слайд с важной текстовой мыслью) — распознаётся и вставляется как текст (переиспользуя существующие конструкции виджета);
- **иллюстрация** (инфографика, схема, скрин интерфейса, где важен именно вид) — вставляется картинкой.

## Решения (брейншторм + ревью Codex)

| Развилка | Решение |
|---|---|
| Источник кадров | И yt-dlp (скачать видео по URL), И локальный mp4/webm рядом с транскриптом |
| Кандидаты | Гибрид двух источников: ffmpeg scene-detection + transcript-cues («смотрите», «скопируйте промпт») |
| Форма пайплайна | Два прохода: contact-sheet триаж → full-res разбор shortlist |
| Распознавание/классификация | Vision-движок: Codex 5.5 при доступности (вне Claude-бюджета), иначе актуальный Sonnet. Внешний OCR не используется |
| Область | Только виджет (Слой 2) |
| Триггер | Opt-in: явная команда «сделай виджет **с кадрами** из X» |
| Архитектура встраивания | Подход A: кадры вписываются в **производную копию** мастер-MD, дальше обычная сборка |

## Зависимость: Шаг 0 — миграция имён

Перед реализацией кадров на этой же ветке выполняется отдельным коммитом **перевод скилла на префиксный словарь имён** по утверждённой задаче [`docs/task-prefixes-by-type.md`](../../task-prefixes-by-type.md): `MASTER_` (был `OUT_…_мастер`), `REVIEW_` (был `OUT_…_обзор`), `WIDGET_` (был `Виджет — …`), при неизменных `SRC_`/`SEC_`. Курсы остаются на `OUT_` → автопоиск серии ищет оба паттерна.

Почему шаг 0, а не отдельная задача: ветка кадров всё равно правит `layer2_widget.md` и `md_parser.py` — те же файлы, что и миграция. Делать кадры поверх старых имён = плодить `OUT_…`, которые тут же придётся переименовывать. Порядок: (1) миграция имён → коммит; (2) кадры поверх новых имён → коммит(ы). У миграции свой DoD и TDD (см. её файл); эта спека лишь **потребляет** новый словарь. Префикс обзора зафиксирован как `REVIEW_` (не `PREVIEW_`).

## Ключевой инвариант (устранение противоречия)

Оригинальный продукт `MASTER_[Название].md` **не редактируется**. Ветка кадров создаёт производную копию `MASTER_[Название]_с_кадрами.md`, в неё вписывает кадры, и виджет собирается из неё. Так «master-MD как продукт не меняется» и «кадры живут в MD» не противоречат друг другу. Виджет на выходе — обычный `WIDGET_[Название].html` (генератор при сборке должен дать имя без суффикса `_с_кадрами`).

> **Имена файлов — новый словарь префиксов.** Спека использует утверждённый словарь `MASTER_`/`REVIEW_`/`WIDGET_`/`SRC_`/`SEC_` (см. [Зависимость: Шаг 0 — миграция имён](#зависимость-шаг-0--миграция-имён)), а не старые суффиксы `OUT_…_мастер`/`Виджет —`.

## Пайплайн (opt-in ветка)

При обычном триггере виджета — поведение без изменений. При флаге «с кадрами»:

```
0. Достать видео     → yt-dlp (URL из шапки транскрипта) ИЛИ локальный mp4/webm
1. Собрать кандидатов → scene-detection + transcript-cues → таймкоды (cap ≤ N)
2. Contact-sheet      → ffmpeg tile: простыня пронумерованных мини-кадров
3. Триаж (Claude)     → по простыне выбрать shortlist 5–15 кадров
4. Full-res разбор    → извлечь shortlist в полном разрешении, Claude классифицирует+распознаёт
5. Вписать в копию MD → текст → блок промпта/спецблок; иллюстрация → ![](path)
6. Обычная сборка     → widget_generator.py (умеет base64-встраивать картинки)
```

## Компоненты

### 1. Входной контракт (откуда видео)

- **URL** — из шапки транскрипта: поле `source:` (Readwise-clipping) → канонический watch-URL (логика уже есть в `source_passport.py`, `_youtube_id`/`passport_from_clipping`).
- **Локальный файл** — mp4/webm, указанный в команде или лежащий рядом с транскриптом.
- Если ни того ни другого нет — мягкая деградация (см. «Обработка ошибок»).

### 2. Добыча видео (`frames_extract.py`, новый)

- **URL** → `yt-dlp` с кэпом качества **720p** (`-f "bv[height<=720]/best[height<=720]"`): 480p не хватает для мелкого текста / IDE-скринов, 720p — разумный баланс читаемости и веса.
- **Cookies** — общая логика cookies (`--cookies-from-browser`, детект устаревших) сейчас в `youtube_to_srt.py` завязана на скачивание субтитров (`-f sb0`). Вынести спецификацию cookies-браузера в **общий модуль**, переиспользовать и там, и здесь (не импортировать субтитровую ветку как есть).
- Видео качается в `frames_work/` в папке серии; по умолчанию **удаляется после нарезки** (тяжёлое). Кадры-кандидаты кэшируются.
- *(Опционально, оптимизация)* до полного скачивания можно взять YouTube storyboards (`-f sb0`) как дешёвый предындекс смен кадра. Помечено как возможное улучшение, не блокирует MVP.

### 3. Сбор кандидатов (`frames_extract.py`)

Два источника таймкодов, объединяются и дедуплицируются:

1. **scene-detection**: `ffmpeg -i <video> -vf "select='gt(scene,<порог>)',showinfo" -fps_mode vfr …` (проверить `-fps_mode vfr` vs `-vsync vfr` для ffmpeg 8.1). Порог 0.0–1.0, **дефолт 0.3**, параметр.
2. **transcript-cues**: из транскрипта берём таймкоды реплик с маркерами показа («смотрите», «на слайде», «скопируйте промпт», «вот код» и т.п.).

Обработка:
- **Дедуп/интервал**: min-gap между кандидатами + отсев near-duplicate (простое сравнение, напр. pHash/SSIM), чтобы скролл/набор текста не давали десятки почти одинаковых кадров.
- **Стабильный кадр**: scene-детект ловит момент *перехода*; финальный PNG снимать со сдвигом **+0.5–1.0 с** от найденного таймкода, чтобы попасть на устоявшийся слайд.
- **Надёжный маппинг таймкод↔файл**: `pts_time` из `showinfo` собирать по порядку и `zip`-ить с реально созданными файлами, **не** полагаться на счётчик `n`.
- **Cap кандидатов**: не более **≤60** на отсмотр (лимит-параметр); при превышении — прорежать по интервалу.

### 4. Contact-sheet и триаж (шаг 2–3)

- `ffmpeg tile` собирает простыню пронумерованных мини-кадров (напр. сетка с номерами-подписями), номер = индекс кандидата.
- Claude смотрит простыню и выбирает **shortlist 5–15** индексов — кадры, похожие на слайд/промпт/ценную иллюстрацию. Читать текст на этом шаге не нужно, только отобрать.

### 5. Full-res разбор shortlist (шаг 4, Claude)

Только отобранные кадры извлекаются в полном разрешении; Claude читает каждый (Read по PNG) вместе с транскриптом и решает:

- **drop** — при full-res оказалось нерелевантно/нечитаемо;
- **текст** — распознать дословно:
  - копируемый промпт/скрипт → **блок промпта** (`.pr-block`);
  - тезис/формулировка слайда → **спецблок** (`> **Метка:** …`);
  - **политика уверенности**: если дословность промпта под сомнением — не текстовый блок, а иллюстрация (+пометка на ручную проверку), чтобы не выдать искажённый копируемый текст;
- **иллюстрация** — инфографика/схема/скрин интерфейса → картинкой.

**Привязка кадр→сегмент:** по таймкоду кадра Claude находит место в транскрипте (у транскрипта есть таймкоды) → нужный сегмент производной копии мастер-MD. Машинная синхронизация не требуется: у сегментов мастер-MD нет собственных таймкодов, привязку делает Claude по смыслу.

**Лимиты вставки:** ориентир **≤12** картинок на виджет и **≤2** на сегмент.

### 6. Встраивание в производную копию MD (шаг 5)

- **Текстовые кадры** — нового кода не требуют: переиспользуют существующий блок промпта и спецблоки.
- **Иллюстрации** — элемент в `### Текст`: отдельная строка `![Подпись · таймкод](frames_work/cand_NN.png)`. Подпись несёт provenance (таймкод/источник) для проверки и пересборки.

### 7. Рендер картинок (`widget_generator.py` + `md_parser.py`)

Правка не «однострочная» — затрагивает несколько мест:
- `md_parser.py`: распознать строку-картинку `![alt](path)` в теле `### Текст` (в `_parse_text`), не спутать с прозой/промптом.
- `widget_generator.py`: прочитать файл → **ресайз + сжатие** (JPEG/WebP для скринов интерфейса, PNG для схем с резкими краями; ограничение по ширине) → base64 → эмитить
  `<figure><img src="data:image/…;base64,…" alt="[экранированный alt]"><figcaption>[экранированная подпись]</figcaption></figure>`.
- CSS: адаптивная картинка (`max-width:100%`), стиль `figure`/`figcaption`.
- HTML-экранирование `alt`/`figcaption`.
- **Вес**: контроль итогового HTML — цель **≤8 МБ**; при превышении сильнее жать/резать или переносить часть кадров в текст.
- Инвариант `✅ JS syntax OK` сохраняется.

## Оркестрация, субагенты и модели

Ветка кадров — механическая и **очень дорогая по токенам из-за изображений**. Поэтому весь vision-объём (триаж + распознавание) выносится из главного Опус-потока: исполнитель «варит» картинки у себя и возвращает компактный JSON (`{таймкод, тип, распознанный_текст, подсказка_сегмента}`), не раздувая контекст мегабайтами PNG. Это не противоречит философии мастер-MD «без субагентов» — там они запрещены ради связности конспекта, а здесь речь про изолированный vision-препроцессинг виджета, не про генерацию смысла.

**Vision-движок: Codex при доступности, иначе актуальный Sonnet.** Проверено на деле (2026-07-02): `codex exec -i <img>` на `gpt-5.5` читает изображения и **распознаёт кириллицу дословно** (промпт распознан точь-в-точь, тип классифицирован верно). Предыдущее «Codex не читает растр» — устаревшая ошибка (та заметка про *генерацию* растра, не про *приём*).

Почему Codex приоритетен: он работает **на бюджете OpenAI — вне токенов Claude**, то есть картинки вообще не касаются контекста Anthropic (максимальная экономия). У `codex exec` есть `--output-schema` + `--json` — Codex отдаёт строгий JSON по нашей схеме.

**Availability-гейт (не хардкодить версии):**
- если Codex CLI доступен (`codex --version` отвечает) → шаги 3–4 идут через `codex exec -i … --output-schema schema.json`;
- иначе → фолбэк на субагент **актуального Sonnet** (модель через алиас `sonnet`, а не пин `claude-sonnet-5` — версия Sonnet со временем меняется);
- на трудных кадрах (мелкий шрифт/шумный скрин), где Codex не уверен, — тот же Sonnet-фолбэк точечно.

| Шаг | Исполнитель | Модель | Почему |
|---|---|---|---|
| 0. Видео (yt-dlp) | Python | — | нет модели |
| 1a. scene-detection | Python (ffmpeg) | — | нет модели |
| 1b. transcript-cues | Python regex (или Haiku) | Haiku (актуальный) | простой паттерн, дёшево |
| 2. Contact-sheet | Python (ffmpeg tile) | — | нет модели |
| 3. Триаж по простыне | Codex → (фолбэк) субагент | Codex 5.5 → Sonnet (актуальный) | отбор мини-кадров; vision вне Claude-бюджета |
| 4. Full-res разбор | Codex → (фолбэк) субагент | Codex 5.5 → Sonnet (актуальный) + политика уверенности | распознавание/классификация; JSON по схеме |
| 5. Вставка в копию MD | Главный агент | Opus (актуальный) | привязка кадр→сегмент и связность — качество-критично |
| 6. Сборка виджета | Python | — | нет модели |
| Реализация + код-ревью | Codex | — | силён в коде |

**Контракт vision-шагов (3–4).** Вход: путь к contact-sheet / папке кандидатов + транскрипт. Выход (строгий JSON по `--output-schema`, тот же формат и у Codex, и у Sonnet-фолбэка): список кадров с полями `{cand_id, таймкод, тип (prompt|slide-text|illustration|drop), текст, подпись, подсказка_сегмента, уверенность}`. Картинки в главный поток не возвращаются — только структура. Единая схема гарантирует, что шаг 5 (Opus) не зависит от того, кто распознавал.

**Мастер-MD режим остаётся на Opus 4.8.** 1М-контекст Sonnet 5 здесь решает несуществующую проблему (транскрипты и так помещаются в 200К), а узкое место — качество сегментации/заголовков, дошлифованное под Опус. Перевод ядра на Sonnet — отдельный контролируемый A/B на одном уроке позже, вне скоупа этой фичи.

## Обработка ошибок (мягкая деградация)

- Видео недоступно (приватное/гео/устаревшие cookies) или yt-dlp упал → предупреждение, собрать **обычный виджет без кадров**.
- ffmpeg отсутствует → явная ошибка с инструкцией (в текущем окружении есть, v8.1).
- Кадр с нечитаемым текстом → в иллюстрацию или drop.
- Битый/отсутствующий PNG при base64 → пропустить с предупреждением, продолжить сборку.
- **Отчёт**: в конце ветки печатать сводку «кандидатов найдено / в shortlist / вставлено текстом / вставлено картинкой / отброшено».
- **Dry-run**: режим «скачать+нарезать+собрать contact-sheet и показать, без правки MD» — для безопасных первых прогонов.

## Тестирование

- **Unit** (`widget_generator`/`md_parser`): `![подпись](fixture.png)` в `### Текст` → `<figure><img src="data:image/…;base64,…">…</figure>`; `✅ JS syntax OK` сохраняется; alt/caption экранируются.
- **Unit** (парсер): строка-картинка не ломает разбор сегмента, не попадает в прозу/промпт.
- **Unit** (`frames_extract`): маппинг `showinfo pts_time`→файлы (zip по порядку); поведение при отсутствии ffmpeg/видео; битые cookies → деградация; соблюдение cap кандидатов.
- **E2E** (ручной): один реальный урок со слайдами — прогон ветки «с кадрами», глазами проверить триаж, распознавание, классификацию, вставку и вес HTML.

## Вне скоупа (YAGNI)

- Режимы master-MD и preview как продукты.
- Внешний OCR (tesseract).
- Автоматическая машинная привязка кадр→сегмент по таймкодам сегментов (их нет).
- Галерея/лайтбокс в виджете — кадры встраиваются как inline-`<figure>`.
- YouTube storyboards как предындекс — опционально, не в MVP.
